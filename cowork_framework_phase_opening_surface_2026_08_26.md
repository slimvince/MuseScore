## 0. Terms, re-explained from scratch, before anything rests on them

Nothing below assumes you remember an identifier. Every term used later is defined here in plain
words.

**The framework phase.** The third of the six ruled phases
(*preparation → pilot → framework → detail specifications → measurement design → audit*). Its job
is to decide the analysis architecture **before** any individual specification is written: how the
analysis is decomposed, what each part is responsible for, and what passes between the parts.

**The frame.** The thing the framework phase produces. It has two levels:

- **Level one — one document, the joint objective.** What the analysis maximizes; over what state
  (key centre × mode × scale-degree chord, with the segmentation of the music into spans treated
  as a variable of the model rather than a fixed preprocessing step); which factors; under which
  ranking of evidence; what is committed and what is carried as alternatives; and what the
  analysis declines to answer.
- **Level two — per-unit sets of statements inside level one**, each required to be consistent
  with the objective.

**A unit.** One of the things level two is written per. Whether a unit is *a factor of the model*
or *a decision the analysis makes about the music* — or a reconciliation of the two — is **not**
fixed in advance; the phase derives it (see §1).

**A statement.** One sentence of specification in the ruled six-field form: (1) what the analysis
must do or be able to do; (2) its defense, each load-bearing claim labelled FACT / THEORY /
CONJECTURE; (3) its source class — derived, salvaged or measured; (4) settled or open; (5) the
premise it rests on and the path by which that premise would fail; (6) what would falsify it.

**The placement test.** The adversarial check on the finished frame. Statements are taken from
**outside** the frame — from ruling records, decision surfaces, dossiers, deferred entries of the
decisions register, the evidence inventory, the declared dormancies, and every current and
previously deleted document heading — and each is placed somewhere in the frame. The brief is
*place these, and report every one you cannot* — never *does this frame look complete?* Every
statement that fits nowhere is a finding about the frame.

**The blindness barrier.** The standing rule that a session deriving specification content may not
read our own code, or any document derived from it. Its purpose: a specification derived from the
code would only restate the code, so the derivation would prove nothing.

**The cross-layer transfer list.** Quoted whole from the phase-definition surface
(`ratification_surfaces/cowork_phase_definition_surface_2026_08_15.md:129–131`):

> the parking list for content found in the wrong layer during derivation, so nothing is silently
> dropped and nothing is absorbed into the wrong charter.

**Claude Code, called CC below.** The coding assistant that runs in the repository on your
machine, one dispatch per session. **The writing side** is the Cowork session — this one — which
writes surfaces, records rulings and writes dispatches to disk. It does not open a dispatch; you
do.

### DECISION 1 — Which side authors the frame, and which side runs the placement test

**The subject, re-explained.** Somebody has to write the frame, and somebody else has to try to
break it by placing statements into it. The plan requires those be different sides, because a side
that authored a frame cannot honestly report what the frame cannot hold. The plan does not say
which side takes which role, and it must be settled *before* the frame is authored: deciding
afterwards means the placement test's independence was never designed in, only claimed.

**What each role actually costs.**

*Authoring the frame* requires: fetching and reading published literature from the open web;
sustained reasoning about music theory including what annotators leave unwritten; and holding the
blindness barrier — no code, no code-derived document — for the whole of a long session.

*Running the placement test* requires: reading a large, scattered population — ruling records,
decision surfaces, dossiers, deferred register entries, the evidence inventory, the declared
dormancies, every current heading, and every heading ever deleted from the document set — and
placing each statement one at a time. The deleted headings can only be recovered from the
repository's history.

**Alternative A — a fresh Cowork session authors the frame; CC runs the placement test.**

*For:* Cowork can fetch and read the literature from the open web, which is source (ii) of the
four and the phase's own opening act. CC's network reach from your machine is uncertain and has
been the constraint before. The placement test is high-volume, mechanical and history-dependent —
exactly what a repository session can pay for and what would exhaust a Cowork session's context
long before the population was covered.

*Against:* CC boots with the whole of `CLAUDE.md` in its context before its first token. So CC
placing statements is not blind to this project's own principles. **This does not defeat the
test** — the placement test requires *non-authorship*, not blindness; nothing in it asks the
placing side to be ignorant. But it must be recorded, because the same boot behaviour is what
voided the derivation method once already.

*Towards the objective:* strong. It puts the literature where it can actually be fetched and the
volume where it can actually be paid.
*Towards the principles:* strong on the theory-grounding rule (an unfetched source yields no
statement); the CC-boot exposure is named, not hidden.

**Alternative B — CC authors the frame by dispatch; a fresh Cowork session runs the placement
test.**

*For:* CC can read the repository's history directly and holds a large context for the source
material. One dispatch produces the frame.

*Against:* CC sits inside the repository, where the code is one command away, and boots
pre-loaded with the governing documents. Authoring the frame is the single act in this project
where the blindness barrier matters most, and this alternative places it in the one environment
that has already breached that barrier by construction. CC's ability to fetch the published
literature is the open question the phase's first act exists to answer — so this alternative bets
the phase's hardest input on an untested capability.

*Towards the objective:* weak. *Towards the principles:* weak — it places the deriving act inside
the known contamination route.

**Alternative C — a fresh Cowork session authors the frame; a second, later fresh Cowork session
runs the placement test; CC does neither.**

*For:* both sides hold the blindness barrier cleanly; the independence is genuine on both halves.

*Against:* the placement population is far larger than one Cowork session can read through the
file bridge, and the deleted-headings half requires repository history that the bridge does not
expose conveniently. The likely outcome is a test run on a much smaller sample than intended, with
the shortfall discovered mid-run.

*Towards the objective:* moderate on independence, weak on coverage.
*Towards the principles:* strong on blindness, weak on the rule that a declared sample be
achievable.

**Alternative D — leave the allocation open and rule it per act.**

*For:* no commitment made before the work's shape is known.

*Against:* this is precisely the defect the plan legislates against — the independence of the
placement test becomes something claimed after the fact rather than designed. It also re-creates
the pattern this project has now hit five times, where a constraint is stated in prose with
nothing that can receive it.

*Towards the objective:* weak. *Towards the principles:* weak.

**Recommendation: A.** It is the only alternative that puts each half of the work where that half
can actually be performed, and its one exposure — CC's non-blindness while placing — does not
touch what the placement test measures. Recorded with it: the frame's author is a **fresh** Cowork
session, not this one, under the standing condition of 2026-08-22 that a blind deriving session is
a fresh Cowork session.

### DECISION 2 — The literature-reachability act: whether it is a separate act, and its stop rule

**The subject, re-explained.** The framework phase's ruled first act is to establish *which of the
published literature this project rests on is reachable at all*. The reason it exists: the
project's own research-papers holding is two files, while the derivation method rests on
literature **fetched and read**. Source (ii) of the four — the state and factor spaces of the
published models — cannot be used at all if the literature cannot be got.

The ruling says the phase *begins* with this. It does not say whether it is a separate, reported
act with its own stop rule, or the first hour of the frame-authoring session.

**Alternative A — the survey is the first act inside the frame-authoring session, reported
alongside the frame.**

*For:* no extra session, no extra record; the person authoring the frame is the person who knows
what they needed to fetch.

*Against:* if the literature turns out to be largely unreachable, that is discovered halfway
through the phase's most expensive act, with a partly-authored frame already resting on three
sources instead of four. There is then no clean point to stop.

*Towards the objective:* moderate. *Towards the principles:* weak — it gives the phase's one
known-fragile input no stop point.

**Alternative B — the survey is a separate, prior act with its own short report and a ruled stop
rule: if the reachable literature does not cover the state and factor spaces of the models this
project rests on, that is a STOP to you, not a licence to author the frame from three sources.**

*For:* the phase's hardest input is tested before anything expensive is spent against it. This is
the identical shape as step zero of the plan, which was ruled with exactly this stop rule — *if
most passages land undetermined the premise is not measurable, and that is a STOP to the user*.
The precedent is the project's own.

*Against:* it is one more act, one more short record, and one more turn of yours. Named plainly
because of the standing bar on process work: **this is an act about the process, not about the
analysis software.** Its cost is small — a survey and a page — and what it buys is that an
unreachable-literature result stops the phase at its cheapest point rather than its most
expensive.

*Towards the objective:* strong. *Towards the principles:* strong — it treats an unfetched source
as yielding no statement, which is the theory-grounding rule, and gives that rule a place to bite
before the spend.

**Alternative C — skip the survey. Author the frame from the three sources that are certainly
reachable, and record source (ii) as a declared hole.**

*For:* fastest. The hole is declared, not hidden, which is the discipline this project already
applies to the pilot's ledger hole.

*Against:* source (ii) is the only one of the four that is external to this project. The other
three are our own schema reading, our own theory reasoning and our own ratified ruling. Dropping
(ii) makes the frame's derivation entirely internal, which is close to the failure the whole
method exists to avoid — and the ruling explicitly says no source is weighted above the others.

*Towards the objective:* weak. *Towards the principles:* weak on the theory-grounding rule.

**Recommendation: B**, with the stop rule stated in the ruling itself so it cannot be softened
later into general advice.

### DECISION 3 — How the placement test's sample is drawn, and when it is fixed

**The subject, re-explained.** The placement test needs a set of statements to place. Ruling 5
dropped the predecessors' pass/fail line but did not say how the set is chosen, and it requires
the report to state the sample's size, the observed proportion of unplaceable statements, and the
uncertainty of that proportion — which is only meaningful if the sample was drawn in a declared
way.

There is a second property, not yet ruled anywhere, that matters more than the size: **whether the
sample is fixed before the frame is authored.** If the sample is drawn afterwards, the frame's
author could — without any bad faith — shape the frame around material they had just been
reading.

**Alternative A — the whole population, no sampling.** Every statement from every named source is
placed.

*For:* no sampling question at all; the proportion is the true proportion.

*Against:* the population is very large. The decisions register alone carries 477 entries; the
heading population and the ruling records add substantially more. The cost is unbounded and
unmeasured, and the pilot's sizing record — the one measurement that might have bounded it — is
labelled NOT A BUDGET, on three named defects.

*Towards the objective:* strong in principle, unachievable in practice.

**Alternative B — a declared stratified sample, drawn and SEALED before the frame is authored.**
One stratum per source kind — ruling records, decision surfaces, dossiers, deferred register
entries, the evidence inventory, the declared dormancies, current headings, previously deleted
headings — with a size declared per stratum, and the drawn set written down and closed before the
frame's author begins.

*For:* it makes the test's independence structural rather than promised, which is the same reason
decision 1 must be settled first. Stratifying by source kind is what makes an unplaceable finding
interpretable — *the frame cannot hold dormancy declarations* is a different finding from *the
frame cannot hold deferred register entries*.

*Against:* declaring the strata is real work, and the deleted-headings stratum requires repository
history to enumerate at all. It also fixes the sample before anyone knows what the frame will look
like, so some strata may turn out to be uninformative.

*Towards the objective:* strong.
*Towards the principles:* strong — a declared sample, sealed, is what makes the reported
proportion mean anything.

**Alternative C — set the sample size from the pilot's sizing record.**

*For:* it uses the measurement the pilot produced rather than inventing a number.

*Against:* the sizing record is labelled **NOT A BUDGET** with three named defects: its blinding
failed; it covers 18 % of its intended input (44 of 241 design-intent entries); and its own
session declared that its clock measures a model's generation time, not an analyst's hours. Using
it to size a different test in a different phase would be spending against a figure its own record
says is not spendable.

*Towards the objective:* weak. *Towards the principles:* weak — it treats a measurement as
established that its own record declares is not.

**Recommendation: B**, with the sealing property written into the ruling explicitly, not left
implicit in the word "declared".

### DECISION 4 — Where the ARM and the SITE get tested, and whether the no-code-sites instruction stands

**The subject, re-explained from scratch.** Field six of every statement says *what would falsify
it*. For a statement about behaviour, the comparison side proposed that field six carry five
sub-fields:

1. the **ARM** — which of three code arms the statement binds: the joint model, the live legacy
   path, or the dormant legacy path;
2. a named **SITE** — the place in the code where the check is made;
3. the **OBSERVABLE** — what is read there;
4. the **DECISION RULE** — the test applied to what is read;
5. the named **near-miss** the statement is *not* falsified by.

All five were carried as **unestablished** — nobody had ever traced a statement into code — and
the pilot's format test was where they were to be tested rather than assumed.

**What the pilot actually returned, read at the object today**
(`cowork_rulings_2026_08_26_sizing_tests_sitting.md` §8.2): the ARM and the SITE are **absent from
all thirty-six statements, by instruction**. The deriving session's brief said naming code sites is
left to a later session, and the session opened no code. So the format test reached **three of the
five**, and — the record's own words — *no output produced under a brief carrying that instruction
can reach the other two.*

**The tension, stated plainly.** Naming a code site means opening the code. A deriving session may
not open the code. So the two sub-fields cannot be produced by any deriving pass, in this phase or
any later one, as long as the blindness barrier stands. This is not an oversight in the brief; it
is a property of the method.

**Alternative A — the instruction stands. The ARM and the SITE are filled in by a NON-deriving
side after the derivation, and are tested there.** The framework phase's statements carry
sub-fields 3, 4 and 5; a named later act, run by a side that is allowed to read code, adds 1 and 2
and is where their testability is judged.

*For:* it preserves the phase's own ruled constraint rather than trading it away. It keeps two
sub-fields that were proposed for a reason instead of discarding them. And it names a side that
**can receive them** — which is exactly the defect the sixty-sixth entry identified as this
project's recurring failure: a disposition that names a destination which cannot receive.

*Against:* it means the frame's statements are checkable in principle but not yet checkable in
fact. That gap must be declared on the face of the frame, not left for a reader to discover.

*Towards the objective:* strong. *Towards the principles:* strong — it holds the blindness barrier
and gives the routed content a real home.

**Alternative B — lift the instruction for the framework phase only. Framework statements name
arms and sites.**

*For:* the two sub-fields get tested immediately, in the phase where the statements are written.

*Against:* it means the frame's author reads code, which is the phase's own **NOT ALLOWED** clause
— *implementation-derived material as design input*. It trades the constraint the whole method
rests on for one test of a form.

*Towards the objective:* weak. *Towards the principles:* weak — it breaches a ruled constraint to
test a sub-field.

**Alternative C — drop the ARM and the SITE from the statement form. Field six carries the
OBSERVABLE and the DECISION RULE only, and connecting statements to code becomes wholly the
audit's job.**

*For:* simplest. It is arguably honest: the audit is the phase whose job is comparing code against
specification, so naming sites there rather than in the specification puts the work where the
capability is.

*Against:* dropping them is a disposal, and this project's disposal discipline requires the worth
test with a finding, a date and a reason. No such test has been run on these two sub-fields. There
is also a real loss: a statement that never names an arm cannot distinguish a requirement on the
joint model from one on a dormant legacy path, and that distinction has already bitten this
project.

*Towards the objective:* moderate. *Towards the principles:* weak on the disposal discipline —
this would discard without the ruled test.

**Recommendation: A.** C may well be right in the end, but it should be reached by running the
worth test, not by omission. A keeps the option open and costs one declared gap on the frame's
face.

### DECISION 5 — The form of the cross-layer transfer list, and whether a second receiver is ruled with it

> **Flagged under the standing bar before it is put:** this decision is about the process, not
> about the analysis software. Its cost is one file and one ruling. What it buys is that three
> named bodies of routed content stop being homeless. **If you judge it not worth its cost now,
> alternative A costs nothing and leaves the defect where it already is.**

**The subject, re-explained.** The cross-layer transfer list is the parking list for content found
in the wrong layer during derivation. This phase opens it — that is ruled. What is not ruled is
what it may receive.

**Why the question arises now.** The sixty-sixth entry's finding was that *a disposition is not a
home unless something can receive it*. Three bodies of content are currently routed to *"the phase
definitions' constraints and stop rules"* — twenty-one rows of the defect catalogue, one half of
one admitted finding, and one further candidate — and the phase definitions live in a frozen
surface whose first line still reads *"NOTHING HERE IS RULED"* and which has no slot for a
constraint added later. The routing is correct and the destination cannot receive. The
cross-layer transfer list is a mechanism of roughly the right shape, which is why the question is
put here and not somewhere else.

**Alternative A — open it narrow, exactly as defined.** One list; entries only for content found
in the wrong *layer* during a derivation pass. The homeless routed material is not addressed here.

*For:* it does exactly what was ruled and nothing more. It costs one file and no new rule. The
homeless material remains homeless, but it is already named in the record, so it is not lost.

*Against:* it leaves a known defect standing with nothing scheduled against it, and this is now
the fifth consecutive occasion on which that defect has been observed and routed around.

*Towards the objective:* neutral. *Towards the principles:* neutral — nothing is broken, nothing
is fixed.

**Alternative B — open it narrow, AND rule a second, separate receiver** for constraints and stop
rules discovered after the phase definitions were frozen, which the frozen surface delegates to.

*For:* each receiver has one admission test and one job. The routed material lands. The frozen
surface stays frozen and gains a delegation rather than an edit, which is how this project already
handles a document that must not be rewritten.

*Against:* one more governing file, in a record the 2026-08-22 direction says should be getting
**smaller**, not larger. That direction is yours and it cuts against this.

*Towards the objective:* moderate — it unblocks nothing in the analysis directly, but it stops a
recurring leak.
*Towards the principles:* strong on one-home-per-concern; weak on the pruning direction.

**Alternative C — open it wide.** One parking list that receives both wrong-layer content and
every statement whose ruled destination cannot receive it.

*For:* one file, not two. Every homeless item has somewhere to go tomorrow.

*Against:* it makes one list serve two admission tests that have nothing in common — *this belongs
in a different layer* and *this belongs somewhere that does not exist yet*. That is the
one-home-per-concern principle applied backwards, and a list with two admission tests is a list
whose entries cannot be audited by either.

*Towards the objective:* weak. *Towards the principles:* weak.

**Recommendation: B if you judge the defect worth a sitting now; A otherwise.** This side does not
press B. The defect is real and recurring, but it is process work, and the standing bar is yours.
