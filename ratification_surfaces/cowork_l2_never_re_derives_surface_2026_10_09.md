## §A.1 What this family is

**The derived statement**, quoted whole from `cowork_blind_derivation_l2_2026_09_27.md` (repository root, line
1143, *checked*):

> **L2-S47. L2 never re-derives an L1 fact. Where it wants something L1 does not publish in usable form, it writes an
> open question naming the input-contract statement that would change, and does without in the meantime. The three
> wants this derivation found are the successor note in a chordal voice (OQ-L2-9), the lowest sounding pitch per slice
> (OQ-L2-11), and an established cue window (OQ-L2-12). A pedal-extended sounding set is not a want: the input contract
> already assigns building it to the consumer.**
> - *Defense.* The charter's layer rule and the fact-publication corollary: "consumers read, never re-derive" [RULED —
>   D-100; principle #7]. The brief's instruction [RULED — brief §3.1]. On the pedal: "a consumer that wants the
>   pedal-extended sounding set builds it from the slices and the span in one step and decides what it means" [RULED —
>   IC beside S-54, Ruling 59]. That is a consumer's act the contract sanctions, not a re-derivation.
> - *Source class.* Given — charter and brief, for the rule. Derived, for the list.
> - *Status.* Settled.
> - *Premise.* The list is complete. **False-negative path:** a want this session did not notice. The falsifier
>   surfaces it.
> - *Falsifier.* CODE. **Observable:** L2's inputs. **Decision rule:** falsified if L2 computes, from L0 facts, any
>   quantity the input contract defines as an L1 publication (a sounding set, a change point, a cue, a relation, a
>   class). **Not falsified by:** L2 reading L0's facts directly for what L1 does not define, such as the key
>   signature's value.

**In plain words.** The note layer below L2 (L1) publishes a fixed list of facts about the music: the slices, which
notes sound in each, where each change point falls, the notated marks and cues, the relation of each note in a voice
to the one before it. L2 — the layer that decides tonality, chord boundaries, chord-tone membership and chords — reads
those facts and never works any of them out again for itself. When L2 needs a fact L1 does not publish, it does not
quietly compute it; it writes an open question naming which line of L1's specification would have to change, and works
without the fact until that is decided. The statement then lists the three such wants the deriving session found, and
says that a fourth thing — the set of notes still ringing under a held damper pedal — is not a want, because L1's
specification already says that whichever consumer wants it builds it itself.

## §A.6 What stands, and what the two questions would decide

**The method that stands** (the derived statements, unchanged by either question): L2 reads everything L0 and L1
publish and nothing else (charter); it never re-derives an L1 fact, and where it wants one L1 does not publish it writes
an open question naming the L1 statement that would change (L2-S47); a fact L1 does not define, such as the key
signature's value, L2 reads from L0 directly (L2-S47's falsifier); the lowest sounding pitch will be read from L1 once
the application act amends S-50 (structural-bass Ruling 2); the pedal reading — the upper-voice chord over a held note —
is scored and chosen inside L2's one decision, the held note assigned as an elaboration (L2-S23; elaboration Ruling 2);
a set of notes ringing under a damper pedal is the consumer's to build from L1's slices and the published span (S-54,
Ruling 59).
