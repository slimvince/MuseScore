## 2. The vocabulary, and terms used below

**Dispositions** as part 1 §2 and the lead-rows surface §2: **ADOPTED — proposed**, **RELOCATED**, **UNPLACED**, and,
where a ruling decides against part of a row, *"decided against in so far as …"*, the re-marking left to the
application act. **The carrier form** is part 1 §3.2's (whether a match is stated per match or a non-tiling span kind is
admitted). **How matching is done** is part 1's wording (its Rows 19.39 (v) and 46.18 (ii)) for key Ruling 1's point
*"Exact or tolerant matching is the detail design's"*.

Three terms of the old catalog that recur, in plain words **[checked at the rows quoted]**:
- **an entry** — one record of the catalog: either a *progression entry* (a named progression, written as its
  functional skeleton) or a *substitution entry* (an operation that replaces a chord with another filling the same
  role);
- **a functional skeleton** — a progression entry written as a sequence of (scale degree, chord quality) pairs relative
  to the key, so the same entry can be placed in any key *(former wording, kept (#12): "so the same entry fits in any
  key" — "fits" is the word key Ruling 1 uses for a match, which this definition does not establish)*;
- **a generative slot** — a member written for any target degree *x* rather than one fixed degree, for example `V7/x`
  (the dominant of *x*) or `subV7/x` (its tritone substitute); the old catalog builds the slot for a given *x* when
  asked (*instantiated on demand*) instead of listing every degree.

Part (i) of each slot row — the slot as a chord defined per target degree — is already proposed RELOCATED to L2 by the
reading file (Rows 57.392 (i), 57.434 (i), 57.504 (ii)), because L2 reads each chord's applied target
**[checked at those rows]**. What stays here is how the catalog holds and uses the slots.
