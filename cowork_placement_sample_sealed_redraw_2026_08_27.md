## 0. The rule this sample was drawn by, and what this file is not

**The selection rule is the writing side's, and the drawing side chose nothing.** The ordering,
the threshold and the take were written out before any item count was known to the side that
applied them, and they were applied mechanically.

**The ordering.** Within each stratum, items are ordered by this tuple, ascending: (1) the
repository-relative path of the file the item is found in, by byte order; (2) then the line at
which the item begins; (3) then, for stratum 8 only, the hash of the commit that deleted the
heading, lexicographically. No other ordering was used — not importance, recency, topic, length
or interest.

**The threshold.** `T = 25`, **DECLARED, NOT DERIVED**. A stratum with `N ≤ T` goes in WHOLE, as
a census. A stratum with `N > T` contributes exactly 25 items.

**The take**, for `i = 0 … 24`, at 1-indexed ordered position:

```
p_i = 1 + ( i * (N - 1) + 12 ) // 24
```

Integer division throughout; `12` is `(T−1)/2` and `24` is `T−1`. No rounding function is used,
because a rounding rule is implementation-defined at exactly one half and this rule must be
deterministic. **A declared and known cost of this rule: item 1 and item `N` are ALWAYS drawn.**
That is a property of the rule, not an error in this draw.

**Fence-awareness.** Everywhere a heading or a list item is counted in this file, the contents of
fenced code blocks are excluded: a `#` line inside a fence is a shell comment, not a heading, and
a `-` line inside one is not a list item. Where the fence-aware and naive counts differ, both are
stated and the excluded lines are named.

**What this file is NOT.** It carries no judgement about whether any item is placeable, no
grouping by topic, no commentary on the frame, and no ranking. **It is a list.**
