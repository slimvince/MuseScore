## 3. Findings (each with file:line and one plain-language sentence)

### Row-anchored (in the disposition CSV, flagged)

1. **default-preset-mode-priors-hand-copied** — `tools/batch_analyze.cpp:196-216`
   (21 rows). `applyPreset()`'s "Default" branch hand-copies the 21 app mode-prior
   defaults from `composingconfiguration.cpp`; sync is enforced only by a code comment
   (no mechanical check) and the values are not recorded in `tools/param_manifest.json`
   (which is chord-scoring scoped) — a value-copied inference-affecting constant
   (guiding #6 / #17f). *(The five NAMED presets instead read the single-source
   `modePriorPresets()` table — published once, consumed, correct.)*

2. **onset-boundary-threshold-hardcoded** — `tools/batch_analyze.cpp:597, 2555, 3718`
   (3 rows). `onsetBoundaryThreshold` is hard-coded to `0.25`, duplicating the
   `IComposingAnalysisConfiguration` default the user-facing bridge reads; a documented
   latent divergence (roadmap 0.6) with no mechanical sync — the two coincide today, but
   a config-default change would make batch stop measuring the user pipeline.

3. **flags-absent-from-help** — `tools/batch_analyze.cpp:3982, 4093` (2 rows).
   `--reachback-ab` and the five `--key-in-*` emission-weight flags are parsed by `main()`
   but appear in neither `printHelp()` nor `BUILD_AND_TEST.md` (documented only in in-code
   comments) — undocumented measurement modes on the shared harness (contract code→doc).

4. **standard-output-crlf-vs-diagnostic-lf** — `tools/batch_analyze.cpp:4593` (1 row).
   The standard analysis output file is opened `QIODevice::Text`, so on Windows the
   committed `.ours.json` corpus is written with CRLF; every diagnostic path writes with
   `std::ofstream(std::ios::binary)` (LF). Confirmed behaviorally this session (standard
   output CRLF, diagnostic output LF). Corpus byte-identity holds only while regeneration
   stays on Windows with Text mode.

5. **exit-path-asymmetry** — `tools/batch_analyze.cpp:4615-4621` (anchored at the `main()`
   row, 1 row). The standard path force-exits (`TerminateProcess` / `std::_Exit`,
   bypassing static destructors to dodge a Qt-TLS shutdown hang), while the ~10 diagnostic
   early-return paths return normally and DO run that destructor sequence; the two exit
   disciplines are inconsistent. Whether the diagnostic returns are ever exposed to the
   same "some runs" hang is unestablished (NOT observed on `--validate-slices` /
   `--decode-chords`, which exited cleanly with their meaningful codes this session).

6. **inventory-overcapture-call-as-function** — `l5_functions.csv` row
   `locateMeasureByTick 748-749` (1 row). Not a second definition — a CALL site inside
   `convertNotationRegion`; the over-capture-biased C++ inventory scanner (bias disclosed
   in `manifest.json`) emitted a spurious function row. The real definition is at 438-470.
   A finding about the inventory extraction, not the harness code; the 870 count includes
   this spurious row.

### Discovered at the harness, not a harness-row verdict (report + register)

7. **param-manifest-line-refs-stale** — `tools/param_manifest.json`. Its

8. **buildtest-lowercase-preset-example** — `BUILD_AND_TEST.md:24, 342`. Both use a
   lowercase `--preset jazz`; the harness matches preset names case-sensitively, so that
   exact command errors ("unknown preset 'jazz'"). Confirmed behaviorally this session
