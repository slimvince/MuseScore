## 3. Task 2 — W2, the delegation bar

### 3.1 The ruling

A delegation admits when it takes one of these forms:

- **an explicit delegation clause** — *"The ratified contract for this layer is X"*, *"The ONE
  detailed cross-layer spec for this contract is X"*, *"formalised as an independent knowledge-base
  component with its own spec (X)"*;
- **a named home with sections** — *"Criterion + build home: X §0/§5.3"*.

A delegation does **not** admit when it is:

- **a bare appended citation** — *"Full spec: X."*;
- **a provenance attribution** — a naming inside a list of citations, or a parenthetical recording
  where something was ratified.

### 3.2 Its defense, which is evidence and not judgment

`open_items/OI-281.md` records that `ARCHITECTURE.md`'s *"Full spec:"* line sits **immediately above**
a line that is an explicit delegation clause of the *"the ratified contract for this layer is"* form.
The canonical document distinguishes the two acts in adjacent lines. Quote both lines at the ruling's
home with their line numbers, re-read this session.

### 3.3 Apply it

Apply to the ambiguous population enumerated at `open_items/OI-281.md` (the documents and their entry
ranges are listed there — cite, do not transcribe the counts). Report which documents admit and which do not,
and the resulting entry movement, from the generator rather than by hand.

**A check you must run before applying:** does this bar change the verdict for any **currently
admitted** document? It should not — the admitted set was reached on explicit delegation clauses —
but that is a prediction, and if any currently-admitted document falls under the bar, **STOP and
report**. That would mean the bar is stricter than the classification it is being added to, which is
a #13 surprise.

## 6. Task 5 — W6, the four mechanisms

**The governing discipline, and it binds this task: build a mechanism only where it removes a
measured failure class, and RETIRE the prose it replaces.** If a mechanism does not let us delete
something, it is apparatus growth — refuse it and report why. We have just diagnosed that this
project's tracking apparatus generates its own defect stream; this task must not feed it.

### 6.1 Mechanism 1 — block shell reads of working-tree files

**Establish feasibility BEFORE building; do not assume.** Determine, from the tooling's own
documentation and configuration, whether a pre-execution hook can intercept the shell path, and
whether it can do so for **both** sides or only for CC's. Report what you find, with its source.

If feasible, implement it to reject the text-utility patterns aimed at repository paths while
allowing the sanctioned uses — `git show` and friends by explicit hash, and the generator and guard
scripts. **If it can cover only one side, say so plainly and do not describe the rule as enforced.**
A control believed to be in place and not in place is worse than none (#19).

### 6.2 Mechanism 2 — the process check

A script beside the existing guards that scans a dispatch or a session report for:

- a bare quantity not adjacent to an artifact-and-field or document-and-line citation (D-431);
- a claim about the code with no `file:line` citation;
- a missing self-check section.

**Establish it the way any instrument must be (#19):** run it over the existing dispatch and report
corpus, where the known instances live — the eight cited in Task 4 — and report its **detection
rate against them**, plus its false-positive rate on text that is correct. An instrument that does
not find the errors we already know about is not established, and reporting that is the right
outcome.

### 6.3 Mechanism 3 — the required self-check section

Add it to the dispatch and report shape, with the checklist named: the guiding principles, the
conventions, the figures-and-premises rule, the file-tools rule, and uncertainty on any comparison
(#24). Its **absence fails the process check** — that is what makes it more than a habit.

### 6.4 Mechanism 4 — triage `CLAUDE.md`

Classify every process rule in `CLAUDE.md` as **mechanism** or **knowledge**. A process rule that
could be a mechanism and is not is a **defect** — row it.

**Execute only where the replacement mechanism exists and passes in the same commit.** For every
other item, produce the triage as a **proposal** and stop: retiring ratified text is a change to what
the governing document says, and it is the user's. `CLAUDE.md` is heavily cited — expect anchor drift
and re-aim **per citation from the drift report's own line numbers**.
