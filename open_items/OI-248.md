# OI-248 — The adapter's meter arithmetic is wrong off common time, and the beat-strength class it feeds is a fitted covariate

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — joint module / metrical facts (declared to Cowork).**

Three connected arithmetic defects in `jointfactadapter.cpp`:

- `nQuarter = ts0.numerator() * 4 / ts0.denominator()` integer-divides (`:352`): 3/8 → 1,
  7/8 → 3, 6/16 → 1 — the bar length the beat classifier reasons against is wrong in those
  meters;
- compound meter is recognized only at denominator 8 (`:119-122`): 6/16, 9/16, 12/16 fall through
  to the simple-meter branch;
- the mid-strong beat class can only fire when `nQuarter == 4` (`:79`) — no mid-bar strong beat
  exists for the classifier outside 4-quarter bars.

The beat-strength class is a FITTED covariate of the segmentation/boundary factor (the Temperley
change-on-strong-beat shape, factorization §7 factor 7), so boundary evidence is systematically
mis-classified in the affected meters. The chorale fit corpus is nearly all common/triple time,
so the fit never sees the error — the envelope pattern again. Shares a design surface with
[[OI-249]] (the grid these classes are computed on). Not fixed here (inference-affecting; its
#8-correct stage, with a refit question since the covariate's fitted values assumed the current
classification).
