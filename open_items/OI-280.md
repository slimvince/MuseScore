# OI-280 — `cowork_progression_schema_dictionary.md` uses the label "D5" for two different decisions

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section F — documentation gap. Rowed 2026-08-03 on the user's ruling of the same date (R5(a) of
`cc_instruction_phase1k_apply_rulings.md`), which directed that the collision be recorded as a row
of its own rather than left inside another entry's provenance. Found by the phase-1j continuation
wave, 2026-08-02, reading the document IN FULL.**

## The finding

The Harmonic Vocabulary's component specification carries a set of locally-numbered component
decisions, and the label **D5** is used twice, for two unrelated rulings:

1. **`:41`, in §1 (What this component is)** — "Owner ruling: **D5** (`cowork_progression_schema_design.md`
   §6), user-ratified 2026-07-02", naming the **dependency-map ownership** ruling: this catalog owns
   the named progressions and substitutions, Layer 5's `functionprogression` owns the pairwise
   licensing grammar, and the two are never derived from each other. The document's own terms table
   points at it by that label as well (`:19`, "the D5 dependency map, §1"). Entered in the decisions
   register as **D-406**.
2. **`:261-263`, in §7 (Component decisions, with the alternatives weighed)** — "**D5** — Harmonic
   scope; voice-leading is a separate dimension held elsewhere", the fifth of the five component
   decisions D1…D5 listed in that section. Entered in the decisions register as **D-408**.

The two labels come from different numbering series — the first is `cowork_progression_schema_design.md`
§6's series, the second is this document's own §7 series — and nothing in the text distinguishes
them. A reader meeting "D5" at `:19` or `:41` and looking it up in the section headed "Component
decisions" finds the wrong ruling.

## Why it is a defect and not a curiosity

`CLAUDE.md`'s Conventions forbid self-invented labels, abbreviations and numbering schemes: "Use the
name a thing already has in the repository; if it has none, describe it in plain words." Two private
series sharing a namespace inside one document is that rule's failure mode — the label carries no
information without knowing which series it belongs to, and neither series is named where it is used.

It is a **documentation gap only**. It is recorded here because it was previously visible only inside
the register entry D-406's provenance field, which is a place for the status of one decision and not
a home for a defect that belongs to the document.

## What is NOT in doubt

Both decisions' content. Both were read in full, entered with the record's own status, and ratified by
the user on 2026-08-03 (D-406 LIVE, D-408 LIVE). Nothing about the ownership split or the harmonic-scope
boundary is in question here — only that one document names two of them with the same handle.

## Disposition

A documentation act at the dictionary's next touch: give each reference the series it belongs to, or
drop the private labels in favour of naming what each decision is (the plain-words option the
convention prefers). Not executed at phase 1k: the dispatch that rowed it licenses no edit to this
document's own content, and the same document's status banner is the subject of the separate
[[OI-281]] question — both edits should land together rather than touching the file twice.
