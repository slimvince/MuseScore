## The mechanism, read at both sources

**`tools/audit/decisions/gen_phase1p_delegation_bar.py`.** Its own docstring states the design:
each authored row carries an ANCHOR, *"a distinctive substring of the delegating line — which this
tool LOCATES in the surface file itself, so the line number and the quoted text come from the file
and not from the author"*, and it lists among what is DERIVED *"each anchor's current line number
and text"*. `RATIFIED_SURFACES` names `ARCHITECTURE.md`, **`CLAUDE.md`** and
`cowork_engage_arc_plan.md`. Its `locate()` returns the one line carrying the anchor, by number, and
raises on absence or ambiguity.

**`tools/audit/decisions/gen_home_classification.py`.** It IMPORTS `locate` and the `FORMS` table
from the delegation-bar tool rather than re-implementing either, calls
`ln, line_text = locate(surface, anchor)` and writes `citation = f"{surface}:{ln}"` into each
entry's `delegation_at` field.

**So both artifacts carry `<surface>:<line>` citations whose line half is re-located on every run.**
That is the right design — it is why a citation cannot silently go stale, and it is the shape
**D-307** exists to protect. **What follows from it is the coupling:** an edit that inserts lines
ABOVE an anchor moves the recorded number, so the committed artifacts stop re-deriving and both
checks go red — while the anchor itself still resolves, uniquely, and nothing about any decision's
home, section or class has changed.

## The firing, established at the objects rather than named as a likely cause

`tools/audit/decisions/phase1p_delegation_bar.json` records the scoring-model delegation at
`CLAUDE.md:1290`, with the delegating line's own text beside it. At this tree that line stands at
**1329** — located by its text with the file tools, and found exactly once. The shift is the size of
the block the 2026-09-07 boot-membership act inserted above it.

**The anchor is still unique, so this is NOT [[OI-330]]'s shape.** There the failure was an anchor
becoming AMBIGUOUS because a second occurrence of a bare filename appeared. Here nothing became
ambiguous: the anchor resolves exactly as before, and only its coordinate moved.

**Both checks are red at HEAD**, and their output says so in their own words — the delegation bar's
*"phase1p_delegation_bar.json does not re-derive"*, and the home classification's four
non-re-deriving `home_section` fields plus *"home_classification.json does not re-derive"*. The four
fields it names are `docs/scoring_model.md` entries, and that file was not touched: what moved is
not their home but the position in `CLAUDE.md` of the clause that delegates to it.

## Why it is worth stating, and what makes it more than bookkeeping

**A dispatch that edits `CLAUDE.md` currently learns about this by turning the guard set red at its
close, after the edit is committed.** The two artifacts are not named among the things a
`CLAUDE.md`-editing act regenerates, the way the session-start read measurement now is.

**And the remedy is not always available to the act that caused it.** `gen_home_classification.py`'s
write mode writes `tools/audit/decisions/backbone_decisions.json`, the decisions register's source
of record, from which `DECISIONS.md` is generated — a write several dispatch shapes bar outright.
Regenerating the delegation-bar artifact alone would leave it inconsistent with the classification
that imports `locate` and `FORMS` from it. So an act can be barred from clearing a red its own
ordered work produced, which is the state the preceding batch closed in and the state this tree is
in now.

**The coupling is a standing property, not something a batch introduced.** It has been dormant
because the batches since 2026-08-18 either did not edit `CLAUDE.md` or did not reach these checks.
