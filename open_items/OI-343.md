# OI-343 — The shell-read guard misses any command whose quoted pattern contains a pipe, because it splits the command into pipeline segments BEFORE tokenizing it

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer (the audit's own guard apparatus), and an
establishment obligation (#19) against an ARMED control. Found 2026-08-04 (CC,
`cc_instruction_c1_ruling_and_item1c.md`) by the guard denying one command after allowing four of
the same kind.**

## How it was found

The guard **fired correctly** on `grep -n "STATUS.md" tools/audit/decisions/gen_cluster_dispositions.py`
and returned its deny message. That denial is what made the four earlier commands visible: this
session had already run four `grep` calls against working-tree files and every one was allowed.

## The mechanism, measured at the guard's own decision function rather than argued

`decide()` calls `split_segments()` — `re.split(r"\|\||&&|[;|\n]", command)` — **before** it
tokenizes. The split runs over the RAW command text, so a `|` inside a **quoted grep pattern** is
read as a pipeline separator. The command is shredded at the alternation, and the segment that
carries the repository path no longer begins with the text utility, so the utility test never sees
the path.

Run over the six commands this session actually issued, the decision function returns:

| command | verdict | first two segments |
| --- | --- | --- |
| `grep -nE "summaris\|recognis" tools/audit/…py cowork_audit_protocol.md` | **ALLOW** | `grep -nE "summaris` ‖ `recognis" tools/audit/…py …` |
| `grep -nEi "carrier\|successors s" tools/audit/…py` | **ALLOW** | `grep -nEi "carrier` ‖ `successors s" tools/audit/…py` |
| `grep -n "carrier\\\|carries the live content" STATUS.md` | **ALLOW** | `grep -n "carrier\` ‖ `carries the live content" STATUS.md` |
| `grep -n "D-642\\\|D-643" DECISIONS.md` | **ALLOW** | `grep -n "D-642\` ‖ `D-643" DECISIONS.md` |
| `grep -n "STATUS.md" tools/audit/…py` | **DENY** | (one segment — no pipe in the pattern) |
| `ls cc_instruction_c1_ruling_and_item1c.md` | **ALLOW** | (one segment — `ls` is not in the utility set) |

**The first four are one defect with one cause.** The sixth is a different and narrower one: D-253
covers *content, existence, line counts and searches*, and an existence check spelled `ls` is
outside the guard's TEXT-UTILITY set, which its own docstring says is the half it covers.

## Why this is the OI-292 lesson in the opposite direction

The guard already carries the measured lesson that **a raw `.split()` splits inside quotes** — the
2026-08-03 false-deny where `grep -c "^  D-" file` was shredded and the fragment `D-"` read as a
repository path. The remedy applied then was `shlex.split(..., posix=False)` **at `tokenize()`**.
`split_segments()` was left splitting raw text. So the same "quotes are not text" error survives one
function upstream of the one that was fixed, and it now fails the other way: then it denied
legitimate work, now it admits forbidden work.

## Dated note — 2026-08-04 (CC, `cc_instruction_guard_fix_and_item1d.md`, Task 1): the cause is confirmed at the code, the corpus was extended BEFORE any rate was re-measured, and the fix is the ORDER rather than a wider pattern

**The user ruled it fixed (R1), and ruled the corpus first.** The ruling states its own reason:
re-establishing against the same corpus would repeat the error being fixed, because the committed
`--establish --check` passed *precisely because* the corpus omitted the defeating shape — so the
published false-negative rate was not a bound on the true one. Task 1 is licensed by **D-641**'s own
stated exception (an establishment obligation under #19 always gates) and by **D-436**, which makes
changing a mechanism that fails a measured condition the user's ruling rather than a session's.

### The cause, discharged at the code and measured (the dispatch's assumption A1)

**A1 is CONFIRMED, and nothing further was found.** The cause is exactly as the dispatch states it:
`split_segments()` cut the command into segments over RAW TEXT, and `tokenize()` applied `shlex`
per segment *afterwards*. Measured at the decision function rather than read off the source, the
guard's own segmentation of the founding command is

```
grep -n "alpha|beta" src/…/keyresolver.cpp
  ->  ['grep -n "alpha', 'beta" src/…/keyresolver.cpp']        ALLOW
grep -n "alpha" src/…/keyresolver.cpp
  ->  ['grep -n "alpha" src/…/keyresolver.cpp']                DENY
```

The second half of A1 — that applying tokenization before the split fixes it — was checked the same
way before anything was edited, against a candidate lexer run over all six shapes.

### The corpus, extended first

`FORBIDDEN` gains the shape in the forms it was actually measured in: Cowork's own run, the four
commands the preceding session issued and the guard admitted, the same shape inside a REAL pipeline
(so a fix must protect the quoted pipe *and* still cut at the genuine one), a real forbidden read
inside a heredoc body that IS executed as shell, and a working-tree read written after a
redirection. `SANCTIONED` gains the control the fix must not break — the same quoted-pipe shape
aimed OUTSIDE the tree — together with [[OI-300]]'s own recorded false-deny shapes (2), (4) and (5),
the hash-bearing git forms D-253 explicitly permits, and the build/test/measurement commands
`BUILD_AND_TEST.md` mandates.

### The fix

**The ORDER, not the pattern.** The whole command is lexed once, with the shell's list and pipeline
operators recognised as tokens in their own right, and the segments are cut at those TOKENS — so a
quoted argument is a single token before any cut is made. The punctuation set is exactly the
characters the superseded regex cut on, so **the only behaviour that moves is where the segment
boundaries fall**; turning every redirection into its own token would be a second behaviour change,
on [[OI-300]]'s shape (5), which this act is not authorized to make. A command `shlex` cannot lex
falls back to the superseded raw split rather than raising, for the reason the tokenizer already
carries: a guard that crashes on a strange command stops guarding.

### The rates, both measured on the SAME extended corpus

`★_the_2026_08_04_segmentation_fix_and_the_corpus_it_is_measured_on`, and none is restated here

move**, so the dispatch's revert condition — *if the fix raises false denials materially, revert and

and none of them is fixed here.
