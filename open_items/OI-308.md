# OI-308 — `--joint-inference` defaults OFF while the joint estimator is the production inference layer — a candidate default flip, for phase 3

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1x, Task 4.3), which names the
behaviour change it refuses to make.**

## The state of affairs

`CLAUDE.md` gate block (A) records the OI-178 adoption: the joint estimator **IS** the production
inference layer on the batch/corpus surface, and every baseline column in that block is measured through
it. On the notation surface the equivalent switch was made by flipping a default — `useJointNotationRecord`
defaults **ON** since the user-ratified notation switch of 2026-07-27.

On the batch surface the default did not move. `jointInferenceDir` is initialised empty
(`tools/batch_analyze.cpp:4917`) and the joint path is entered only when it is non-empty (`:5590`). So the
production inference layer is reached only by a caller who remembers a flag, and the dormant pipeline is
what a caller gets by default.

## The case FOR flipping it

- **It is the same act already ratified on the other surface.** The notation switch made the record arm
  the default precisely so that the in-app analysis is the production one unless something explicitly asks
  otherwise. The batch surface is the one the gate is measured on, and it still defaults the other way.
- **Every omission found by the phase-1x audit is an instance of it.** The authoritative command reference
  documented a flag-less invocation ([[OI-307]] fact 2), and a session following it measures the dormant
  pipeline without being told. Correcting each site is treating instances; the default is the cause.
- **A default that must be remembered is a default that will be forgotten**, and the failure is silent —
  nothing in the output, the manifest or the guard says which arm ran ([[OI-307]] fact 3).

## The case AGAINST, and why nothing was done

- **It is a behaviour change, and D-231 forbids one in phase 1.** Issue-exhaustion and specification
  completion come before any fix design; this is a fix.
- **It would not be one revertible commit's worth of nothing.** The flag's default governs what
  `test_batch_analyze_regressions.py` pins, what every `--dump-*` diagnostic sits beside, and what the
  retired batch diagnostic (`characterise_bir_false.py`, whose `52/24/52` sets are legacy-pipeline
  figures) measures. Flipping it makes the legacy figures unreachable without a new opt-out flag, which
  is a second design decision riding on the first.
- **It is #14 territory:** a behaviour change is user-ratified as one revertible, provenance-stamped
  commit, and this is not that commit.

**It was deliberately not taken.** The phase-1x dispatch names this limit in terms, and the wave corrected
the documentation instead.

## What is NOT in doubt

That the adoption happened and that the joint estimator is the production layer on this surface — gate
block (A) states it and its baselines are measured through it. This row is about how that layer is
REACHED, not about whether it is the production one.
