# OI-215 — The joint decoder returns an EMPTY analysis (0 segments) on most orchestral scores — a robustness cliff, not just a cost

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — the analysis-cost / notation-surface cluster (decoder robustness; a STOP, #13)**

**The surprise (a STOP, surfaced not built around).** In the analysis-cost dispatch's decode profile
(`cc_instruction_analysis_cost_profile.md` Task 1), TWO of the four decoded orchestral scores —
butterworth "Banks of Green Willow" (1100 events) and holst_mercury (1743 events) — decoded to
**ZERO committed segments**: `decodePiece` runs the full DP for 10–14 s and returns
`complete = false` with an **empty analysis** (no segments, no record). The chorale/keyboard perf corpus
and the other two orchestral scores decoded normally. This is the exact exposure the dispatch flagged:
an orchestral score is a class the decoder has never seen.

**The mechanism — code-proven, a theorem not a correlation.** `decodePiece`'s semi-Markov Viterbi
requires every event to be covered by a contiguous segment of ≤ segCap (=4) events, and a candidate
`(key, class)` for a segment is SKIPPED (content = −∞, `jointdecoder.cpp:773`) unless ≥2 of its members
are present in the segment's ONSET-pc union (the ≥2-member content gate, `jointdecoder.cpp:444-445`). So
an event is UNCOVERABLE iff EVERY ≤segCap segment containing it has an onset-pc union with **< 2 distinct
pitch classes** — then no class can have 2 members present, no candidate survives for any covering
segment, the DP cannot reach the final boundary, and `V[N].states.empty()` → `complete = false`, 0
segments (`jointdecoder.cpp:838-841`). **A single uncoverable event GUARANTEES an empty decode.** (The
root-present prune only removes further candidates, so the onset-diversity test is a sound sufficient
condition — it under-counts uncoverable events, never over-counts.)

**Why chorales never hit it and orchestral scores do.** A 4-voice chorale onsets ≥2–4 distinct pitch
classes in essentially every 4-event window, so uncoverable events never arise (measured: 0 on all four
perf-corpus scores and on all 326 chorale fits). Orchestral textures routinely have a passage where,
within any 4-event window, only ONE instrument onsets a single pitch class while the rest sustain — a
solo line over held harmony, a monophonic link, a unison — producing an event with < 2 distinct onset
pcs in every covering window. The decoder was fitted and its segCap/gate ratified on the homogeneous
chorale corpus (OI-39), where this structural case does not occur.

**The measured extent (`tools/notation_seams/large_score_profile_counts.json`, `uncoverableEvents`
scan; the instrument scans the adapter's event lattice for the sufficient condition above).** **13 of
the 23 committed large scores have `uncoverableEvents > 0` and therefore produce a GUARANTEED empty
whole-piece decode** — every symphony in the set: Beethoven 7 (60), Beethoven 9 (55, both uploads),
Holst Planets (38), Haydn 8 (27), the Schubert D.810 quartet (23), Holst Mercury (13), Dvořák cello
concerto mvts I/III (4/7), Butterworth (3), Tchaikovsky 1812 (3), Haydn 6 (2), Gluck Iphigénie (1). The
2 decoded instances (butterworth, holst_mercury) confirm the theorem; the other 11 are theorem-
guaranteed (they exceeded the decode cost cap and were not force-run). The 10 with `uncoverableEvents =
0` (the Brandenburg concertos, the B-minor Mass, the Art of Fugue, Dvořák symphony 9 mvt I, Fauré
quintet, both Jupiter uploads, Dvořák cello mvt II) may decode, subject only to cost.

**Consequence for the analysis-extent decision (OI-210) and the large-score requirement (OI-209).** For
these scores the question is not "does whole-piece decode cost too much" ([[OI-209]] cost profile) but
"does whole-piece decode produce ANY answer" — and for the majority of the orchestral set it produces
NONE. This is a decoder/robustness limitation independent of the cost/latency axis, and it bears on
every extent candidate: a bounded-window or enclosing-unit decode that happens to fall on an uncoverable
run would return empty for that window too. **Declared to Cowork; NOT fixed here** (a read-only
measurement, and any fix — a relaxed content gate for sparse-onset windows, a larger segCap, a
silence/monophony-tolerant segmentation, an all-events-covered fallback — is an inference/layer design
decision, not a knob-turn, fixed at its #8-correct stage). Related: [[OI-206]] (the record path this
decoder feeds), [[OI-18]] (the specified-not-coded extension cluster), the whole-system architecture
review's Tristan stress case ([[OI-209]], `cowork_architecture_review_2026_07.md` §7).
