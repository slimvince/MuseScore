## What the check was, and what it returned

Read wave 1 established that **D-058** — one of three decisions the 2026-08-01 adjudication names as
provably invisible to the harvest's signature net — had been entered with unusual care and never
checked against the code afterwards ([[OI-315]]). The dispatch's Task 2 was to identify the other two
from the adjudication's own record and check each against the code.

**The three, identified from the record and not from memory.** The harvest note on [[OI-207]]
(2026-07-28) names them — *"the priority-of-evidence table `:3134-3141`, the slicer boundary row
`:1045`, the piece-start shortcut `:3128-3130`"* — and the adjudication note (2026-08-01) gives their
register ids: *"the priority-of-evidence table (**D-057**), the slicer boundary rule (**D-042**), the
piece-start shortcut (**D-058**)."* `tools/audit/decisions/decision_inventory.md:629-637` states the
same three in its own recall note. **Every cited line number has drifted** (the priority table is now
`ARCHITECTURE.md:3549`, the slicer row `:1281`), which is why they were located by their quoted words.

**The result: both siblings are TRUE at HEAD.**

- **D-042** — *"Boundaries = the sorted-unique union of every onset AND every release of the eligible
  notes"*. `src/composing/analysis/slicing/slicer.cpp:31-49` does exactly that: the comment states the
  rule, the loop skips non-eligible notes and pushes `e.onset` and `e.release` for the rest, and
  `:53-54` sorts and dedups. (The joint fact adapter's separate re-implementation of the boundary rule
  is [[OI-239]] and is not this row's subject.)
- **D-057** — the priority-of-evidence table, ranking actual sounding notes strongest, the notated
  signature weak and the mode tag weakest. `src/composing/analysis/key/keyresolver.cpp:255-369` still
  implements it: the signature is a scoring prior inside the inferrer, the declared mode reaches
  `analyzeKeyMode()` as a hint, the mode tag enters only through the insufficient-data fallback at
  `:329-331`, and the former hard declared-mode promotion is recorded as REMOVED at `:358-367`.

So the class [[OI-315]] found is **bounded at one instance** among the three.

## The finding this check produced instead

D-057's statement did not go stale; its **home moved under it**.

`ARCHITECTURE.md:3510-3518`, added at phase 1z, scopes the section the table lives in:

> *"§5.2 describes the **LEGACY key path** … **It is NOT the production key path**, which is the joint
> estimator's decode (§3.3; register entry D-051). Nothing in §5.2 describes what the shipped analysis
> does on the key axis."*

`open_items/OI-228.md:26-28` cites that same table as one of the sources the joint emission departs
from — *"the priority-of-evidence table ranks 'Actual sounding notes — what is literally happening
now' the STRONGEST evidence"* — and the register's own `status_source` for D-057 says *"Cited by
open_items/OI-228 as the primary source the joint emission departs from."*

**So a premise a live open item puts under load is homed in a section that now disclaims describing
the arm that open item is about.** Two readings are possible and neither is written down anywhere:

1. the priority ranking is a **cross-cutting evidential rule** binding both arms, which happens to be
   stated inside a section about the legacy path — in which case the scoping sentence needs a carve-out
   and OI-228's citation stands; or
2. it is a **legacy-path rule**, in which case OI-228's departure claim needs a source that binds the
   production arm, and D-057's `status_source` overstates what it carries.

This row does not choose. Which arm an evidential contract binds is a decision about the production
emission, not a wording fix.

## A second, smaller defect in the same paragraph pair

`ARCHITECTURE.md:3543` reads *"The priority of evidence, which now has no exception, is:"* and `:3562`
reads *"The inferrer output is used for all but **one** narrow fallback case"*. Read plainly the two
contradict each other; and the first predicate names no argument — no exception **to what** — which is
the qualified-predicates standard (`cowork_design_doc_template.md`). The intended reading is *no
PIECE-START exception*, which is what the immediately preceding paragraph establishes and what the
phase-1z correction was making. It is recorded here rather than corrected, with the two other §5.2
findings.
