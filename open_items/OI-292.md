# OI-292 — Ten `CLAUDE.md` rules could be enforced by a mechanism and are not; the strongest is that no check confirms the four local patches are still present

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section F — Doc-sync debt (#10). Rowed 2026-08-03 by the phase-1p dispatch's own instruction
(`cc_instruction_phase1p_home_rulings_and_mechanisms.md` §6.4): "A process rule that could be a
mechanism and is not is a **defect** — row it."**

## What was done

Every rule `CLAUDE.md` carries was classified MECHANISM-EXISTS / MECHANISABLE-AND-NOT / KNOWLEDGE.
The population is DERIVED, not searched for: it is every register entry whose home is `CLAUDE.md`,
the register having enumerated that document in full (protocol P1). Only the class of each rule is
authored, and each carries the mechanism that covers it or the ground on which no mechanism can.

The artifact is `tools/audit/claude_md_rule_triage.json`, generated by
`tools/audit/claude_md_rule_triage.py`. Its `totals`, `rules_total` and `the_defect_set` carry the
counts; nothing is transcribed here (**D-431**).

## The defect set

`the_defect_set.ids` names them. They fall into five families:

- **★ The file-tools rule itself — BUILT AT PHASE 1p AND NOT ARMED, which is why it stays in this
  set.** `tools/audit/shell_read_guard.py` is committed and established (8 of 8 forbidden forms
  denied, 0 false denies over this session's real commands). Arming it means one block in
  `.claude/settings.json`, and `.gitignore:112` puts that file outside the record as "Claude Code
  local session state". **A live control existing only in an untracked file is the [[OI-285]] class**
  — a change on disk and not in the record, which no later reader can find and no commit can revert —
  so the guard was deliberately left unarmed rather than switched on invisibly. The arming block is
  written out verbatim in the tool's own docstring. Two things ride with the user's decision: the
  settings watcher may need `/hooks` opened once before a newly added hook fires, and the exec form
  takes an absolute path, so a TRACKED form of the block would need one that is not machine-specific
  — which makes *should `.claude/settings.json` be tracked at all?* a real question rather than
  something to settle by force-adding the file.

- **The four local patches — the strongest candidate, and it is a real exposure.**
  `CLAUDE.md`'s "Local patches — do not revert" section carries four edits to code this project does
  not own, each stated as do-not-revert **against a dependency update**. A dependency update that
  reverts one is exactly the silent failure a check catches and a reader does not: nothing fails, the
  tests pass, and the patched behaviour quietly returns to upstream's. A check that each patch is
  still present in the file it patches is a few lines and has no false-positive mode.
- **Two same-commit rules stated as conditions on a diff.** A scoring change and its documentation
  land together; a new ruling and its register entry land together. Both are stated in exactly the
  form a pre-commit check takes, and the first even names an arithmetic staleness check — the
  template count in the scoring document against `kTemplateCount` — that nothing performs.
- **Two convention checks over prose.** The reserved music-theory vocabulary (the collided words are
  enumerated in the rule itself, and the convention is mechanical: the bare word is musical, every
  non-musical use is qualified), and the no-self-invented-labels rule, which admits only a weak
  candidate-flagging form.
- **Two measurement rules.** That every reported comparison carries its uncertainty (#24) — the
  process check has the adjacent half and not this one — and that a newly acquired corpus enters as
  research material, which the corpus manifest could carry as a tier the gate tooling refuses to
  measure against.

## What is NOT owed

`the_defect_set` is not a build list. Each member needs the same thing every mechanism in this wave
needed before it: an established form (#19) — a measured detection rate against real violations and a
measured false-positive rate on legitimate work — because a guard that fires on legitimate work gets
switched off, which is worse than no guard. The two built at phase 1p carry theirs
(`tools/audit/process_check_establishment.json`, `tools/audit/shell_read_guard_establishment.json`).

## What this triage did NOT do, stated because it is the point of the exercise

**No `CLAUDE.md` text was retired.** The dispatch's governing discipline is that a mechanism must let
us delete something, or it is apparatus growth. Neither mechanism built in this wave retires prose:
the process check makes **D-431** and **D-434** checkable without replacing their statements, and the
shell-read guard would enforce part of **D-253** while the rule's scope, its exemption and its
measured defense must all stay readable. That is recorded in the artifact's `what_was_executed`
rather than glossed, and it is the honest answer to the discipline's question: these mechanisms
remove failure modes, they do not shrink the governing document.

Whether that is a good enough reason to keep them is the user's call, and undoing either is small —
the guard is not armed, and the check is a script nothing depends on.
