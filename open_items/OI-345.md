# OI-345 — The shell-read guard is armed on the PowerShell tool and its utility set contains no PowerShell reading verb, so `Get-Content`, `Select-String` and `Get-ChildItem` aimed at a repository path are allowed

**Section D — instrument / measurement layer (the audit's own guard apparatus). Found 2026-08-07

## The finding

`tools/audit/shell_read_guard.py` enforces **D-253** — working-tree content, existence, line counts
and searches go through the file tools, never through shell text utilities. Its own docstring
records the hook block it is armed with, and that block's matcher is **`"Bash|PowerShell"`**: the
guard is invoked for the PowerShell tool by design. **Its `TEXT_UTILITIES` set is POSIX-only.** No
PowerShell reading verb is in it — not `Get-Content`, not `Select-String`, not `Get-ChildItem`, not
`Measure-Object`, not `Test-Path`.

**Measured at the guard's own `decide()` rather than reasoned from its source**, over the three
commands this session actually issued plus the bare cmdlet forms:

| command | verdict |
|---|---|
| `powershell.exe -NoProfile -Command "(Get-Content 'C:\s\MS\STATUS.md' \| Measure-Object -Line).Lines"` | ALLOW |
| `powershell.exe -NoProfile -Command "Get-ChildItem 'C:\s\MS\BUILD_AND_TEST.md',… \| Select-Object Name,Length"` | ALLOW |
| `powershell.exe -NoProfile -Command "Select-String -Path 'C:\s\MS\DECISIONS.md' -Pattern … \| Measure-Object"` | ALLOW |
| `Get-Content C:\s\MS\STATUS.md -TotalCount 20` | ALLOW |
| `Select-String -Path C:\s\MS\CLAUDE.md -Pattern 'foo'` | ALLOW |
| `Test-Path C:\s\MS\CLAUDE.md` | ALLOW |
| `cat C:/s/MS/STATUS.md` | DENY |

Every one of the first six does exactly what the last one does and exactly what D-253 forbids — a
line count, an existence-and-size listing, and a search, all of working-tree files. The guard's
reason string for all six is *"no text utility is aimed at a repository path"*, which is true of the
set it carries and false of the command it read.

## The establishment half, which is why this is not merely a coverage remark

**Measured over the guard's own corpus:** its `FORBIDDEN` list (23 entries) and its `SANCTIONED`
list (31 entries) contain **zero** PowerShell reading verbs between them; the only PowerShell member
of either is the build invocation `Start-Process`, which reads nothing. So `--establish` re-derives
the guard's recorded deny rate and false-deny rate exactly, and **those rates are silent about this
whole family** — a figure that is current, reproducible and blind, which is the condition **#19**
exists to refuse. **It is [[OI-343]]'s shape one shell dialect over**, and [[OI-343]]'s own
resolution states the order the user ruled for exactly this: **the corpus goes first**, because
re-establishing against a corpus that omits the defeating shape repeats the error being fixed.

## The session's own conduct, recorded beside the guard's

**This session broke D-253 three times**, all at its start and all through the PowerShell tool: a
line count of `STATUS.md`, a size-and-existence listing of twelve working-tree files, and a search
of `DECISIONS.md`. They were read-only metadata queries used to choose a reading strategy, and none
of them fed a recorded value; every content read thereafter went through the file tools. **The
guard's miss is why the session was not stopped, not why it did it** — the same sentence
[[OI-343]]'s row records about its own finder.

## What is NOT in doubt

No analysis, no analysis input, no corpus, no measurement of the analysis, and no register entry or
status is touched by this. **The POSIX half of the guard is unaffected** and its recorded rates
re-derive; the git-object exemption behaves as recorded; and the `decide()` results above are
reproducible by running the function over the same command strings.

## Why the fix is NOT made here

Adding the PowerShell reading verbs to the utility set is a change to a MECHANISM that fails a
measured condition, which **D-436** makes the user's ruling rather than a session's — and the order
[[OI-343]]'s ruling fixed applies unchanged: the corpus is extended with the defeating shapes
BEFORE any rate is re-measured, or the new rate is silent in a new place. There is also a second
question a session may not settle: PowerShell's reading verbs have aliases that collide with the
POSIX names already carried (`cat`, `type`, `ls`, `gc`, `sls`), so whether the remedy is a widened
name set or a per-dialect model is a design call, and the guard's own docstring already records that
parsing a shell command line without a model of shell syntax is the family [[OI-300]] names.

## Dated note — 2026-08-08 (CC, `cc_instruction_guard_dialect_close_and_push.md`, Task 1): the corpus went first, the blindness was measured before the widening, and the previous rates were BLIND rather than wrong

**The user ruled it fixed (R1 of 2026-08-07), and ruled the corpus first**, adopting the order
[[OI-343]]'s ruling had already fixed for the POSIX side. The ruling states its own reason and this
note does not restate it (#6): re-establishing against the blind corpus would repeat the error being
fixed, because `--establish --check` passed *precisely because* the corpus omitted the family.

### Assumption A1 discharged — the vocabulary is SOURCED, and the alias route came back SUFFICIENT

The dispatch's A1 asks whether the family and its aliases can be enumerated from PowerShell's own
alias table rather than authored ad hoc, and names the failure it is guarding against: *a vocabulary
assembled until the answer comes out right*. **It can, and it was.** The cmdlets are chosen by a
stated rule — the PowerShell commands that perform one of the four acts **D-253** itself names
(content, existence, line counts, searches) on a path argument — and every alias is read out of
`Get-Alias -Definition <cmdlet>`. The sourcing command, the pinned version and the enumerated names
are recorded in the establishment artifact, not here (**D-431**).

**The version is pinned and the limit is stated rather than papered over**, which is the accepted
outcome the dispatch names for this assumption: the alias table is a property of the HOST, not of
the language, so the enumeration is only as wide as the version it was read on. **PowerShell 7 is
not installed on this machine**, so its table could not be enumerated and **no claim is made about
it**; the sourcing command is recorded so a session on another version can re-run it. Carrying a
name some other host does not alias costs detection nothing — it simply never matches.

### The blindness, MEASURED at the unwidened guard, which is what the old rates could not show

Every row added to the corpus was decided at the **UNWIDENED** guard first — the committed
POSIX-only utility set, with the extended corpus already in place. **Every forbidden form of the
dialect was admitted, and no sanctioned form of it was denied.** The counts are in the artifact and
none is restated here (**D-431**). What it establishes in words: the guard was **not wrong** about
this family — it could not see it at all, which is exactly the shape of a rate that re-derives
exactly while bounding nothing.

### The widening, and why it is a parameter model rather than a longer name list

The utility set gains the family and its aliases. The candidate-path selection for those names is
**derived from the cmdlets' own documented parameter positions**: within this family a path binds
either as the value of `-Path` / `-LiteralPath` / `-FilePath` or as the FIRST positional argument,
never both, so those are the only two places examined; `Select-String` and `Measure-Object` have
their first positional dropped, being a pattern and a property name. **That is not decoration.**
Without it a pipeline-fed `Select-String -Pattern 'FAIL'` reads as a repository file named `FAIL`
and a `-TotalCount 20` reads as a repository path named `20` — the [[OI-292]] false-deny shape
reproduced in a new dialect, which is how a guard gets switched off. The limit is stated in the
function itself: only the first positional argument is considered, so a form whose ONLY repository
path is a later positional argument is missed.

### Both rates on the SAME extended corpus, and the revert condition

Every value is at `tools/audit/shell_read_guard_establishment.json` →
`★_the_2026_08_08_powershell_dialect_widening_and_the_corpus_it_is_measured_on`, and none is
restated here (**D-431**). In words: **detection rises sharply and the false-deny count does not
move at all**, so the ruling's revert condition — *a material rise in false denials* — is **NOT
met**. Every false deny that remains is one [[OI-300]] already records as owed, and none is fixed
here.

### Assumption A2 discharged BY MEASUREMENT, not by argument

The dispatch makes any POSIX-side verdict change a STOP. Every row the corpus carried **before** this
act was decided with the POSIX-only set and again with the dialect, and **not one verdict moved**.
The check is written into the artifact so it re-runs on every `--establish`, rather than being a
claim this session made once.
