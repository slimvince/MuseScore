# OI-311 — `gen_ratification_surface_set.py` has no verify-only mode, so it cannot be run as a guard without overwriting its own committed artifact

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1x, Task 2), assembling the
derived guard list.**

## What is missing

Every other generator in the audit set carries a `--check` (or `--verify`) mode: re-derive, compare
against the committed artifact, exit non-zero on drift, write nothing.
`tools/audit/gen_ratification_surface_set.py` has none. Its only mode writes
`tools/audit/ratification_surface_set.json`.

## Why that makes it unrunnable as a guard, rather than merely inconvenient

The artifact's `census_scope.files_scanned` counts files in the tree. **Any wave that adds a file changes
it by construction** — phase 1w's report already recorded exactly that, "one field moved and reported
rather than glossed". So running the generator to find out whether anything drifted is guaranteed to
change the artifact, and in this session it would have folded phase 1x's own new files into phase 1w's
**uncommitted** record before that record was committed.

That is the [[OI-301]] hazard in its second instance: a mode whose only way of answering a question is to
destroy the record it is asked about. It is recorded as NOT RUN, with this reason, at
`tools/audit/guard_state.json` → `not_run`.

## What the fix looks like

A `--check` that re-derives into memory and diffs, exactly as its siblings do — the pattern is already
written in `gen_phase3_gate_partition.py` and `gen_nongating_apparatus_rows.py` and needs no invention.
The one judgment it needs is what a file-count field should do in check mode: a census whose scope is
"the tree" cannot be byte-stable across waves, so either the count is excluded from the comparison and
reported separately, or the check reports it as expected movement rather than drift. That is a small
design decision and it is the reason this is rowed rather than done in passing.

## What is NOT in doubt

That the generator itself is correct and its derivation established — phase 1w drove it and reconciled
the one moved field against the committed object by hash. This row is about the absence of a way to ASK,
not about the answer.

## On whether this row gates

It reads like apparatus — a tracking artifact's verification mode. But the non-gating set is DERIVED
from an over-inclusive first cut over the subject column, and that cut did not propose this row;
hand-adding a verdict is the hand-listing `CLAUDE.md` forbids. So it **GATES by default**, on the
[[OI-306]] precedent. Independently, the establishment its fix ends in gates on its own account under
D-438's establishment clause.
