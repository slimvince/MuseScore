# OI-381 — the session-start read measurement overstated its own subject: it counted `CLAUDE.md` WHOLE as an ordinary session's read after eight of that file's spans became conditional, and its own `--check` passed while it did

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Rowed 2026-09-07 (CC, `cc_instruction_read_size_repair_and_rows_2026_09_07.md` Task 3(a)) and
RESOLVED in the same batch (Tasks 1 and 2).** The identity was MEASURED at the INDEX before it was
written, not asserted: the highest row identity `OPEN_ITEMS.md` carries is `OI-380`, and a directory
search of `open_items/` found no `OI-381.md`.

**Why both acts sit in one batch.** Register rule (c) requires a newly discovered issue to get an
index row and its detail file in the commit that records the discovery; rule (d) requires a
resolution to flip its row with provenance. The discovery was made by the preceding batch, whose own
bars forbade opening a row, and the repair is this batch's Task 1. Both obligations are therefore
discharged here, and neither is skipped on the ground that the other is satisfied.

## The defect

`tools/audit/gen_session_start_read_size.py` measures **what an ordinary session reads at session
start**, and it is the tool the whole pruning arc reports its savings with.

Its authored `MEMBERS` table named `CLAUDE.md`, and `measure()` computed `len(claude_md)` for it —
the WHOLE FILE. That was right while the whole file was the read. **On 2026-09-07 the user ruled
that it is not**: six spans of `CLAUDE.md` are read at session start and eight are read only when
the session's work touches them.

From that ruling onward the measurement counted **eight CONDITIONAL spans into a read no ordinary
session takes** — which is precisely the error the tool's own docstring already refuses in terms:

> *"A CONDITIONAL read (`BUILD_AND_TEST.md`, `docs/scoring_model.md`, the joint estimator's section)
> is NOT a member: it is read by the sessions its condition names and not by an ordinary one, which
> is what CONDITIONAL means."*

**A second, smaller fault sat beside it.** `CLAUDE.md`'s member row cited no clause — it read *"the
project instructions themselves, which every clause below is written in"* — where the other two rows
each quote a real clause of `CLAUDE.md`. It was written when no clause existed to cite. Since
2026-09-07 one does.

## Why it is more than a nit

**It is the measurement the arc's savings are reported with.** Every act of the pruning arc has had
to state what it saved, and this tool exists so that those values enter by citation to a generated
artifact rather than by transcription (#17f, **D-431**). A measurement that overstates its own
subject makes every saving reported through it a claim about a read nobody takes.

**Its own `--check` could not see it.** `--check` re-derives the artifact and compares the rendered
text against the committed one. The fault was in the **DEFINITION** of what is measured, not a
drift, so the definition re-derived identically and **the check passed while the measurement
overstated**. That is the silent-failure direction #19 exists against: a thing merely unfalsified is
not established.

## What was done — the repair, and the four checks that establish it

**The repair (Task 1, commit `61e9e6e54d`).** `CLAUDE.md`'s contribution is now the sum of the SIX
session-start spans. The EIGHT conditional spans are measured BESIDE the read and never summed into
it, each published with what it is and the condition that calls for it — the treatment
`FURTHER_SPANS` already had, for the reason stated there. Where a conditional span overlaps a
session-start one, the shared characters are published, so an overlap is visible rather than silent.

**Nothing was authored.** Every span name, every heading and every anchor is PARSED out of
`CLAUDE.md`'s own membership block, on the idiom `rule_a_pointer()` already used and for the reason
that function's own comment gives: a later amendment of the membership moves the measurement without
anybody editing the tool. Every span is named by its HEADING and never by a line number (**D-307**),
each heading found exactly once in heading form or the run STOPs; the two spans that are not
headings are located by the anchors the block itself quotes, sought OUTSIDE the block, because the
block quotes the anchors it names spans by and the naming is not the thing named.

**The member row's clause is now the real one**, quoted out of the block rather than retyped — a
retyped sentence would be one more transcription site in a file that already carries the three
[[OI-377]] rows.

**The two regimes are STATED rather than inferred.** A `CLAUDE.md` carrying no membership block is
read whole (`regime: "whole-file practice"`); one carrying it is read at the six spans
(`regime: "ruled membership"`); a block present with an unresolvable span is a STOP. Every movement
row names the regime on BOTH sides, because a comparison across a regime boundary compares two
different questions. **Both recorded earlier commits resolve to the whole-file regime, and that is
MEASURED at their git objects rather than inferred from how the tool describes them** — which is the
check the dispatch ordered, the writing side having declared the point inferred.

**The four establishment checks (Task 2), all published in the artifact or the report:**

1. **The overstatement is MEASURED, not asserted** — the former whole-file value and the repaired
   six-span value are computed at the SAME tree and their difference published at
   `tools/audit/session_start_read_size.json` → `at_the_tree` → `the_reading_of_claude_md` →
   `★_the_overstatement_this_repair_removes`. No figure is restated here (#17f, **D-431**).
2. **Reproduce-check** — the artifact written, then two further independent derivations each
   compared byte-for-byte against it by `--check`, both passing.
3. **Reconciliation in both directions** — every span resolved is one the block names, every span
   the block names was resolved, none in both and none in neither, and no two spans share a name.
   A mismatch in any direction is a STOP, not a reported field.
4. **A falsification test, run on every run** — if the six spans ever cost at least as much as the
   whole file the tool STOPs, because a membership costing the whole file has not been derived but
   mis-parsed.

**One bound on check 4 is declared rather than left unstated (#24).** The test RUNS on every run and
did not fire at this tree. Its FIRING was not exercised on a synthetic input: doing so needs either
an edit to `CLAUDE.md` or a new probe file, and this batch's bars admit neither. What is established
is that the test runs and passes, not that it has been seen to fire.
