# OI-306 — A third over-breadth class of the process check, measured and not yet in its published corpus

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1w) from running
`tools/audit/process_check.py` over this wave's own dispatch, which the dispatch asks for.**

## The class

The check's **"uncited code claim"** rule fires on the words *reachable*, *dormant* and *unreachable*
in the phase-1w dispatch. In every instance the dispatch is either

- **quoting** the row the wave is executing — *"for each marked entry, is its subject reachable on
  either production surface at HEAD"* is `OPEN_ITEMS.md` OI-289's own sentence, reproduced with its
  citation — or
- **defining the vocabulary of a test** — the four reachability senses a verdict must name are the
  dispatch's own definitions, not assertions about what the code does.

And the facts that *do* make code claims sit two lines above, each with its `file:line`. So the rule
is firing on the one part of the document that is deliberately not a claim.

## Why it is the same shape as the two classes already published

`tools/audit/process_check_establishment.json` → `known_over_breadth_do_not_tune_it_away` records two
classes already: a **structural description that carries a number and a unit noun** read as a bare
quantity, and a **section reference written without the section mark** (`Task 2.3`) read as the same.
Both are the check lacking a model of a construct — a description, a cross-reference. This is the
third: **no model of a quoted or defined term.**

## What must NOT be done

Special-casing the three words. That artifact forbids it in terms and gives the reason: a pattern
adjusted until a particular sentence passes is tuned to a specimen, and the same objection holds in
both directions. The words are also exactly the vocabulary any future reachability or liveness work
will use, so an allowlist would blind the check on the documents it most needs to read.

## What is owed

The treatment the second class got at phase 1s: **the specimen enters the CONTROL corpus**, both rates
are re-measured, and the published false-positive rate **RISES visibly** — so the class becomes a
known property of the check rather than a defect designed around. Extending a mechanism's corpus
re-measures its rates, which is a mechanism act under **D-436** as amended on 2026-08-03: report, do
not execute. That is why this row exists instead of an edit.

## What is NOT claimed

That the check is wrong to have found them. Under D-431's letter a two-place liveness word without a
citation beside it is what the rule is built to catch, and the rule catching it in a definition is
over-breadth, not error — which is the distinction the two published classes already draw.

**Dated note — 2026-08-04 (CC, READ WAVE 3, `cc_instruction_reads_3.md`, Task 7): the same class
again, on the same word, in THREE further constructs the check has no model of — and one of them is
the document doing exactly what the rule wants.**

Running the check over this wave's dispatch returns **findings in two classes only**, both already
published or rowed: seven in the user-ACCEPTED section-reference class (`Task 1.1`, `Task 4.2` and
so on read as bare quantities), and four in THIS row's class, all on the word *reachable*.

What the four add is that the constructs are new. This row recorded two — a quotation and a
definition. The wave-3 dispatch supplies three more:

1. **An interrogative.** *"is the fine-grain function override on the legacy path, or reachable on a
   production surface?"* — a question the dispatch is ORDERING to be answered, not a claim.
2. **A conditional stating a stop condition.** *"If it is reachable on production, STOP and report"*
   — a rule about what to do if a fact turns out one way, which asserts nothing about HEAD.
3. **★ A self-labelled ASSUMPTION.** *"**A2.** That the fine-grain function override is on the
   legacy path rather than reachable on a production surface. **This is Cowork's inference from the
   joint estimator being production, not a read fact.**"*

The third is the sharpest specimen the class has produced. The dispatch does precisely what a
citation rule exists to make people do — it states the claim, labels it an assumption in bold, says
in terms that it is not a read fact, and schedules a task to check it at the code. The check flags
it anyway, because it has no model of the assumption-labelling construct, which is the construct
#17(a) requires.

**Nothing is tuned.** The remedy is unchanged and unchanged for the same reason: these specimens
enter the CONTROL corpus, both rates are re-measured, and the published false-positive rate rises
visibly — a mechanism act under **D-436**, reported and not executed. The word *reachable* is also
now doubly the wrong thing to allowlist: this wave's Task 4.2 answered that very question at the
code, so a check blinded to the word would be blinded to exactly the sentences that carry the
project's liveness findings.
