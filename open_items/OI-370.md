## What was established, and at which object

**The obligation, read at `CLAUDE.md`.** Its build-and-test section states: *"Always read
these three files at the start of every session"*, naming `BUILD_AND_TEST.md`, `STATUS.md`
and `DECISIONS.md`, and adds: *"Do not rely on memory of previous sessions for baseline
numbers or iteration state — read STATUS.md."* The current handoff entry point repeats it as
reading order 5.

**The obligation cannot be discharged.** Three attempts this session, with what the file

| Attempt | Result |
|---|---|
| Whole file | REFUSED — reported 60,306 tokens against a 25,000 cap |
| `offset 0, limit 60` | REFUSED — reported 37,832 tokens |

So a session performing this mandatory read reaches the banner and the top few entries, and
nothing else.

**The remedy is already stated by the document itself.** `STATUS.md`'s own banner reads:
*"Historical entries live in `STATUS_ARCHIVE.md` (reference-only, NOT part of the
session-start read) — a superseded entry moves there instead of accumulating here."* The rule
is in force; what is missing is its application. The live file carries many entries from a
narrow window of days, each a single dense paragraph.

**The precedent for the act exists.** The doc split that created `STATUS_ARCHIVE.md` and
`cowork_handoff_archive.md` is recorded at `cc_instruction_doc_split.md`, so this is the
repeat of an act already performed once, not a new kind of act.

## Why it is worth a row rather than a remark

**A mandatory read that cannot be performed is not a size complaint.** Every session since the
file passed the threshold has been working from a prefix of a document the governing
instructions send it to for current baselines and iteration state — and **nothing reports
that**, so the shortfall is invisible at the point where it matters.

It is the shape the record already names twice. The never-work-from-memory rule's founding
instance is a session reasoning from neighbouring documents without opening the specification
that stated the answer explicitly and twice. Ruling 64's own grounds put it in one line:
*route-on-demand fails under load.*
