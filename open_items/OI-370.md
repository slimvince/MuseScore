# OI-370 — A mandatory session-start read cannot be performed: `STATUS.md` has accumulated past the point where the file tools can read it

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section F — doc-sync debt (#10). Found 2026-08-11 (Cowork) while performing the
session-start read the handoff prescribes.**

## What was established, and at which object

**The obligation, read at `CLAUDE.md`.** Its build-and-test section states: *"Always read
these three files at the start of every session"*, naming `BUILD_AND_TEST.md`, `STATUS.md`
and `DECISIONS.md`, and adds: *"Do not rely on memory of previous sessions for baseline
numbers or iteration state — read STATUS.md."* The current handoff entry point repeats it as
reading order 5.

**The obligation cannot be discharged.** Three attempts this session, with what the file
tools returned:

| Attempt | Result |
|---|---|
| Whole file | REFUSED — reported 60,306 tokens against a 25,000 cap |
| `offset 0, limit 60` | REFUSED — reported 37,832 tokens |
| `offset 0, limit 18` | Succeeded |

So a session performing this mandatory read reaches the banner and the top few entries, and
nothing else.

**The remedy is already stated by the document itself.** `STATUS.md`'s own banner reads:
*"Historical entries live in `STATUS_ARCHIVE.md` (reference-only, NOT part of the
session-start read) — a superseded entry moves there instead of accumulating here."* The rule
is in force; what is missing is its application. The live file carries many entries from a
narrow window of days, each a single dense paragraph.

**The precedent for the act exists.** The doc split that created `STATUS_ARCHIVE.md` and
`cowork_handoff_archive.md` is recorded at `cc_instruction_doc_split.md`, so this is the
repeat of an act already performed once, not a new kind of act.

## Why it is worth a row rather than a remark

**A mandatory read that cannot be performed is not a size complaint.** Every session since the
file passed the threshold has been working from a prefix of a document the governing
instructions send it to for current baselines and iteration state — and **nothing reports
that**, so the shortfall is invisible at the point where it matters.

It is the shape the record already names twice. The never-work-from-memory rule's founding
instance is a session reasoning from neighbouring documents without opening the specification
that stated the answer explicitly and twice. Ruling 64's own grounds put it in one line:
*route-on-demand fails under load.*

## What is NOT claimed

**No gating verdict.** Whether this row gates is derived from a cut and is never hand-added —
the lesson OI-336 records and the change D-436 reserves. The row reports the question and
proposes no verdict. *The question itself, stated so it is not lost:* the subject is the
record's own apparatus, which the non-gating declaration classes non-gating; but the
consequence is that a session may not know the analysis's current state, and D-438's second
half reaches a statement about the analysis or its build state. Left for the derivation.

**No count of what should move.** How many entries are superseded is a derivation over the
file, not a judgment made in a row.

**Nothing about the analysis** — no measured value, no golden, no corpus of scores, nothing
in `tools/robust_stop/`.

**Not that any session was harmed.** That an obligation could not be discharged is
established; that a specific session reached a wrong conclusion because of it is not, and
would need its own measurement (#19).

**The three values above are this session's own observations**, produced by the file tools'
own refusals rather than by a generated measurement. They are stated with the mechanism that
produced them because that mechanism is the finding. A durable version is a generated check —
see closing act (b) — which is what D-431 asks of a value meant to be relied on.

## The closing acts

**(a) Apply the archive rule the document's own banner states.** Superseded entries move to
`STATUS_ARCHIVE.md`, which is reference-only and explicitly not part of the session-start
read. Nothing is deleted; the archive is the pointer that makes the move lossless (#12).

**(b) Detect the condition rather than discover it.** A size guard in the guard set, so a
mandatory read passing the threshold reports itself. This is a mechanism addition and the
mechanism set is FROZEN, so it is PROPOSED here and not taken. It is the record's own
strongest habit applied to itself: this project's declared STOPs have caught its premise
errors, and reading has caught almost none.
