# OI-310 — Three ratified `CLAUDE.md` rules carry no authored mechanisation triage, and the check that says so was not being run

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1x, Task 2).**

## What the check reports

`tools/audit/claude_md_rule_triage.py --check` exits non-zero: **D-437, D-438 and D-439 have no authored
triage.** The tool classifies every `CLAUDE.md` rule into MECHANISM-EXISTS, MECHANISABLE-AND-NOT or
KNOWLEDGE, and refuses to report a clean run while a rule is unclassified. Complete output at
`tools/audit/guard_state.json` → `runs`.

## Which wave introduced it — this one IS establishable

The three are the entries the last two waves added, and `STATUS.md` records both events: phase 1o took the
register **436 → 438** (D-437, D-438), and phase 1v took it **438 → 439** (D-439). So the check has been
failing since D-437 and D-438 were entered, and the triage table was not extended in either commit.

That is the ordinary shape of this defect and it is worth naming: the register's same-commit rule (rule
(c)) covers the register's own files, and the triage is a separate authored table in a separate tool, so
adding an entry does not prompt anyone to extend it.

## Why it was not noticed

The same reason as [[OI-309]] and [[OI-305]]: this check is in no recent wave's reported guard list. It is
now in the derived population of `tools/audit/gen_guard_state.py`, so a future wave that skips it will
show it skipped rather than absent.

## Why nothing was fixed

Task 2 of the phase-1x dispatch forbids fixing what it finds. Beyond that, the triage verdicts are
**authored judgments** — whether a rule can be enforced by a mechanism at all, and whether one exists —
and D-437, D-438 and D-439 are governance rules (the apparatus-row non-gating declaration, the phase-3
gate partition's authority, and the discovery-channel enumeration). Classifying them is exactly the kind
of judgment the tool refuses to guess, and a session should not guess it either.

## What is NOT in doubt

That the three entries exist and are ratified; that the check is behaving as designed; and that nothing
about the failure bears on any measurement — the triage is a record of what could be mechanised, not an
input to anything.

## On whether this row gates

It reads like apparatus — a record of what could be mechanised, an input to nothing. But the non-gating
set is DERIVED, by an over-inclusive first cut over each row's subject column, and that cut did not
propose this row. Hand-adding a verdict for a row the cut never reached is exactly the hand-listing
`CLAUDE.md` forbids, so the row **GATES by default** and the [[OI-306]] precedent applies: if it belongs
in the apparatus class, the cut is what should reach it.
