# OI-374 — Four guards print through a stream the shared encoding module does not reconfigure, so the guard runner's captured output follows the environment rather than the tree — and the artifact's own ground for trusting the run is not true of them

**Section D — instrument / measurement layer. Found 2026-08-12 (CC,
`cc_instruction_resume_lapse_records.md` Task 2) while verifying that task's own claim at the
objects, which is what put the difference in front of a reader.**

## How it was found

Task 2 claimed that the only movement in its regenerated artifacts was the open-row count. Verifying
that claim meant diffing the two commits as git objects rather than describing the change — and the
diff carried one line nobody was looking for: the guard runner's captured output for
`tools/open_items_split_check.py` changed from `OVERALL PASS <replacement character> bijection
holds` to `OVERALL PASS — bijection holds`, with the tool unedited between the two runs.

**This is the residue of the condition [[OI-373]] recorded and explicitly did not diagnose.** That
row states that the committed guard artifact did not re-derive at this tree while its verdict set
was identical, and says in terms that which tool's text moved was not established. This is that
tool, and this is the cause.

## What is established, at which object

**The mechanism, read at the two tools.** `tools/audit/output_encoding.py` reconfigures **the
calling process's own** standard streams; it sets no environment variable, so a child process
launched by the guard runner inherits nothing from it. `tools/audit/gen_guard_state.py` runs each
guard as a child and decodes its output as UTF-8 with `errors="replace"`. A child that does not
reconfigure its own stream therefore encodes with whatever the environment gives it, and any byte
that is not valid UTF-8 reaches the artifact as a replacement character.

**The demonstration, run both ways rather than argued.** `tools/open_items_split_check.py` was run
twice at this tree, unedited, with only the interpreter's output encoding changed between the runs.
Under the locale codepage its em dash arrives as a replacement character; under UTF-8 it arrives as
an em dash. **Neither run changed the verdict** — both are `OVERALL PASS` — which is why this can
sit in a guard artifact unnoticed: what moves is the captured text and never the exit code.

**The population, derived rather than listed.** Every `*.py` under `tools/` was searched for a call
to the shared module, and the result was compared against the guard runner's own invocation table.
**Four members of the run set do not call it:** the open-items bijection check and the notation-seam
call-path check — both authored by name from outside `tools/audit/` — and two inside it, the
decisions-register check and the finish-line route check. Whether each of the other three prints a
character outside ASCII was NOT tested; only the first is demonstrated above.

**The artifact's own ground, read at the artifact.** `tools/audit/guard_state.json` carries a field
whose whole job is to say why its run can be trusted: *"Every guard here routes its printing through
tools/audit/output_encoding.py, so a findings list can no longer be truncated by a character the
console cannot encode."* **That sentence is not true of the four members above**, and the reason it
matters is the one the sentence itself gives — the module exists because a check once exited
non-zero having printed a clean-looking summary and none of what it found ([[OI-305]]).

## Why it is a row rather than an act

**The remedy is a change to guards this dispatch may not touch.** Three of the four are outside
`tools/audit/` or outside this batch's subject entirely, and adding a call to a shared module is a
mechanism change **D-436** reserves — the same reason [[OI-373]] authors no invocation. Nothing here
proposes a design.

**And the artifact's own sentence is the sharper half.** Correcting the four tools would make the
sentence true; correcting the sentence alone would leave the exposure it describes. Which of those
is done first is not decided here.

## What is NOT claimed

**No verdict moved, and none is claimed to have moved.** Every guard's pass or fail is unaffected by
its output's encoding; what this row is about is the captured TEXT and the artifact's reproducibility.

**The failure mode is NOT demonstrated on this tool.** What the module was built against is a
`UnicodeEncodeError` that truncates a findings list. An em dash is inside the locale codepage here,
so it degrades silently rather than raising. Whether any of the four would truncate on a character
outside that codepage is **not tested and not asserted** — the row records the missing coverage, not
an observed truncation.

**No gating verdict.** Whether this row gates is derived from a cut and is never hand-added
([[OI-336]], **D-436**).

**Nothing about the analysis.** No behaviour, no measured value, no golden, no corpus of scores,
nothing under `tools/robust_stop/`. The subject is the audit's own guard apparatus and one field of
its own record.

## The closing acts, neither of them this session's

**(a) The four guards route their printing through the shared module**, after which the artifact's
sentence is true of every member and the captured text stops following the environment.

**(b) Or the sentence is bounded to the members it covers**, which is the honest smaller act and
leaves the exposure standing where a reader can see it.
