## The decided method

The ratified `cowork_joint_estimator_factorization.md` specifies the pitch emission as
`P_emit(tone | k, c; covariates)` — **per tone** — and its 2026-07-19 granularity amendment
evaluates the pitch and spelling emissions **per tone**, specifying the bass factor as "each
event's **sounding** bass against the segment's chord". The emission's covariate set includes
**tied-over preparation**, which presupposes that tones arriving by tie are emitted at all.

## The layer decisions it departs from (the primary source, read this session)

- `ARCHITECTURE.md:1045` — the Layer-2 slicer's boundaries are "the sorted-unique union of every
  **onset AND every release** of the eligible notes".
- `ARCHITECTURE.md:1047-1053` — a slice is "constant **tonal** sonority"; a non-boundary-opening
  note "still rides along in each slice's `overlapping()` set (passed through, not dropped)";
  **"Slice identity is the eligible sounding-NOTE set"**.
- `ARCHITECTURE.md:3134-3141` — the priority-of-evidence table ranks "**Actual sounding notes** —
  what is literally happening now" the **STRONGEST** evidence, above temporal context, the
  notated signature and the mode tag.

## The implementation (CC code-confirmation, read-only, 2026-07-28)

- `jointdecoder.h:67` — `notesByEvent` is documented verbatim as "note indices whose **ONSET** is
  in event e (non-anacrusis)". The per-event tone set is onset-only by construction.
- `jointdecoder.cpp:298-301` — the emission is summed over that onset set:
  `for (int idx : piece.notesByEvent[e]) { … b.emission += adapter.emissionLogp(…, n.tied != 0); }`.
- `jointdecoder.cpp:117` and `:369-370` — the bass factor is `eventBassPc(*this, notesByEvent[e])`
  / `eventBassPc(piece, piece.notesByEvent[i])`, i.e. the "sounding bass" the factorization names
  is computed from the **onset** set, not the sounding/overlap set.
- The sounding set is available and used elsewhere — `piece.overlapPcs(i, j)` (the pitch classes
  sounding over a segment) drives the augmented-sixth display derivation
  (`jointnotationrecord.cpp:78`) — but the emission does not read it. Cross-checking against the
  fit tables, a note already sounding (onset earlier) can only ever **spare a chord a
  missing-template-tone penalty**, never **support** it, because the penalty is the one place a
  sounding-but-not-struck tone is consulted.

## The mechanism that ties the two layers together (the sharpest statement)

The slicer creates a boundary at every **release**, by design, because a note ending changes the
sonority (`ARCHITECTURE.md:1045`) — and those are exactly the moments at which nothing is struck.
The OI-199-pass-2 fire-count histogram records **428 windows with zero distinct onset pitch
classes**. So the architecture, working correctly, manufactures the moments at which the emission
concludes there is no pitch evidence. One layer publishes the sounding set on every slice; the
consumer does not read it.

## The two caveats, carried honestly

- **(a) refit constraint — with a CC sharpening.** The note tables were FITTED by counting tones
  in some particular way; correcting the decode without refitting would leave the model reading
  one thing through numbers calibrated to another. **CC code finding that sharpens this:** the
  factor-presence table's own provenance (`jointembeddedartifacts.cpp:118`,
  `membership_definitions`) declares **"overlap"** the **PRIMARY** membership — "a factor sounds
  if a note's `[onset,onset+dur)` overlaps the segment (a factor held over from the previous
  chord still sounds)" — with **"onset"** only a **CROSS-CHECK**. So at least that fitted table
  was calibrated on the sounding/overlap notion while the decode's emission walks the onset set —
  the decode already reads an overlap-fitted table through an onset lens. The full
  which-table-uses-which-membership map (the `emission.levels` distribution, the note tables) is
  the [[OI-207]] adjudication's to settle; declared to Cowork, not resolved here.
- **(b) consequence unmeasured.** The admission gates fail loudly and were therefore found (the
  empty-decode cliff, [[OI-215]]/[[OI-227]]); the emission miscounts **silently**, so wherever
  admission happens to succeed on a sustained texture the reading may still be skewed — an
  accuracy question **everywhere**, not a coverage question in one place.

## The user's position, recorded

A note that is already sounding is part of the sonority, and whether it belongs to the chord is
what the emission's chord-member / non-chord-tone categories are for. The "held notes are weaker
evidence" argument does not survive: the fit corpus is voices and organ — sustaining throughout —
so the decay reading never applied even where the model was fitted.

## Relation to the remainder of the family (why no fix here)

This is the emission face of the same shape as the admission cliff: the model reads **struck**
notes where the design says **sounding**. [[OI-215]] (member-overlap admission on sparse
windows), [[OI-227]] (fit/NCT-budget admission on dense windows), and [[OI-226]] (candidate
admission has no ratified basis) are the admission faces; this row is the emission face. Designing
a fix over part of a family is the patch-per-symptom error (#6/#7), so the [[OI-215]] fix surface
is DEFERRED until the whole family is enumerated and one design covers it under the Premise Gate
(#17). This row is a conformance gap **declared**, not fixed (a read-only dispatch; any fix is an
inference/layer decision at its #8-correct stage, never a knob-turn).
