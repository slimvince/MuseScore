**Section D — joint decoder / robustness (a STOP, #13; declared to Cowork)**

The governing question of `cc_instruction_oi199_joint_p3_p4.md` — **is [[OI-215]] alone?** — is answered
by measurement: **NO.** The empty-decode family has TWO candidate-admission failure gates, at opposite
ends of the onset-density spectrum. This row is the SIBLING; [[OI-215]] is the other.

**The measurement (`tools/audit/oi199/joint_firecount_large.json`, `scanCoverage` over the 23 committed
large scores, 172,611 events).** 312 events are structurally uncoverable (every ≤ segCap covering window
admits no candidate → `V[N]` empty → 0 segments):
- **291 (93.3 %)** — the [[OI-215]] MEMBER-OVERLAP gate on SPARSE windows (< 2 distinct onset pcs).
- **21 (6.7 %)** — this SIBLING: the **FIT / non-chord-tone-budget gate** (gate 3,
  `jointdecoder.cpp:448`): `(nOnset − present) > max(1, j−i)`. Located in **holst_planets 14,
  tchaikovsky_1812 5, beethoven_sym9 1 + its openscore upload 1.**
- 0 `rootOnly` (gate 1 never solely blocks), 0 `memberOverlapRich` (gate 2 fires only on its < 2-pc case).

**Mechanism (the OPPOSITE extreme to OI-215).** A `fitBlocked` event is so DENSE — many simultaneous
onset pcs — that no 3–4-member chord can fit: any class that clears gate 1 (root present) and gate 2 (≥ 2
members present) still leaves `nOnset − present` non-chord tones far above the budget `max(1, j−i) ≤ 4`
(the segment length), so gate 3 rejects it, and every covering window is that dense → the event is
uncoverable. OI-215 is the SPARSE cliff (too FEW onset pcs for member-overlap); this is the DENSE cliff
(too MANY onset pcs for the NCT budget) — chromatic tutti writing (Holst's planetary chords, the 1812's
cannon tutti). Same all-or-nothing empty result (#12), a DIFFERENT gate.

**★ It also means OI-215's own measurement instrument undercounts.** The `< 2 onset pcs` proxy in
`large_score_profile_counts.json` (the scan that founded OI-215) is a sound sufficient condition for
member-overlap ONLY; it is blind to this FIT-gate sibling. The REAL-`candidateStates` scan
(`scanCoverage`) finds the true uncoverable count is **312, not 291** — the proxy undercounts by exactly
these 21 events (see the [[OI-215]] dated note).

**Why it matters (#3 / #6 / #7):** the OI-215 fix must cover the WHOLE family. A relaxation of the
member-overlap gate for sparse windows leaves all 21 dense `fitBlocked` events (and every future one)
still emptying the decode. ONE design at the candidate-admission layer must cover both gates — and give
admission its first ratified basis ([[OI-226]]). Enumerating the family before designing is exactly what
this dispatch exists to do (#3: a surprise means the fact basis was incomplete; do not build around one
instance).

**NOT fixed here** (read-only characterization; any fix is an inference/layer design decision at its
#8-correct stage, under the Premise Gate, never a knob-turn). Caveat: measured with the production top-6
