# OI-287 — The ratification surfaces and the dispatches have no directory of their own, and moving them re-aims cited paths

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section F — doc-sync debt (#10) / repository organization. Rowed 2026-08-03 at phase 1l on the
user's ruling of the same date ([[OI-285]] option (a) plus a directory convention), which resolved
the commit half and left the filing half as its own act.**

## What the user ruled, and what this row carries

The ruling on [[OI-285]] had two parts: **commit the ratification surfaces**, and **give the class a
directory**. The first is executed at phase 1l — all seven `cowork_decisions_pending_ratification_*`
files plus the phase-1k dispatch are committed **in place**, at the paths they already had. The
second is rowed rather than executed, and this row says why.

## Why the move is its own act

**Nine committed register entries already cite these paths as the provenance of a ratified
decision.** D-406…D-414 each record their ratification as "the phase-1j queue presented at
`cowork_pending_ratifications_next_session.md` §2", and that document in turn names
`cowork_decisions_pending_ratification_8.md`. Moving a file re-points every citation of it. That is
not a filing decision — it is an edit to provenance fields the user has ratified, which is exactly
the class of change [[OI-285]] itself said a session must not make on its own judgment.

**And the citations are not confined to the register.** The same filenames appear in `STATUS.md`
entries, in the dated notes on several open items, and in each phase dispatch. A rename that fixes
the register and leaves the rest dangling is worse than no rename.

## The constraint any move must satisfy

**Every citation is re-aimed PER CITATION, from the drift report's own output — never by an assumed
path rewrite.** `gen_cluster_dispositions.py --verify` reports each unresolved reference
individually, and that report is the input to the correction, one line at a time. This is the same
discipline the phase-1i/1j/1k waves used for line-number drift, where an assumed uniform shift would
have silently mis-aimed anchors that had not moved by the same amount. A path rewrite has the same
failure mode with none of the visibility: a `sed`-style sweep produces a tree in which every
reference resolves and some of them resolve to the wrong thing.

A move therefore owes, in one act: the new directory named and its membership rule stated (which
classes of document belong — the ratification surfaces, the dispatches, both, or something
narrower); the files moved; every citation re-aimed from the verify report; the three guards run at
the committed tree; and the register's provenance fields re-read to confirm each now resolves to the
file it means.

## What is NOT in doubt

That the files are now committed and therefore durable — the exposure [[OI-285]] found is closed.
This row is about where they live, not about whether they survive.

## Disposition

For the user or for Cowork, not a session: name the directory and its membership rule, then the move
runs as one commit with the per-citation re-aim above. Until then the files stay where they are, and
every citation resolves.

**★ Dated resolution note — 2026-08-03 (CC, phase 1u, Task 4), executing the user's ruling of the
same date (option 4A: a directory for the ratification surfaces only).**

**The directory is `ratification_surfaces/`** — the record's own phrase for the class (this row's
title, [[OI-285]]'s title, and the ruling's own words), not an invented label. **Its membership rule:
a document whose own opening declares it a ratification queue or a ratification review aid.** Ten
files moved with `git mv`, so history follows them.

**★ THE DERIVED MEMBERSHIP CAME BACK AMBIGUOUS, AND THE AMBIGUITY IS REPORTED RATHER THAN HIDDEN.**
The dispatch directed the set be derived from what register entries actually cite as ratification
provenance, not from a list. Derived three ways at
`tools/audit/ratification_surface_set.json` → `readings`, the counts and members being fields there
(**D-431**):

- **DIRECT** — members a register entry's own provenance names in a ratification sentence. This is
  the instruction read literally, and it returns **one** file.
- **REACHED** — members a direct member names in turn. The register cites a queue document's §2, and
  §2's content is a pointer to the complete-entry aid, so a reader following the provenance lands on
  both.
- **CLASS** — every document whose own banner declares it one, cited or not.

**What was done and on what ground:** the CLASS was moved. The ruling says *"the ratification
surfaces"* in the plural, and a directory built on DIRECT holds one file while nine siblings stay in
the repository root — which does not do what the ruling asked. The instruction's *"not from a list"*
is satisfied because CLASS is derived from each document's own banner rather than enumerated by
hand. **If the narrower reading was meant, the reversal is one move per file and the artifact names
them all.**

**One member was NOT moved, deliberately:** `cowork_pending_rulings_2026_08_02.md` is untracked, and
moving it would commit it. Whether the repository keeps that document is the [[OI-285]] question,
which the user ruled once for the seven pending-ratification surfaces and has not been asked about
for this one; its own banner calls it removable. It stays where it is and is reported.

**The per-citation re-aim ran as the constraint above requires** —
`tools/audit/reaim_ratification_surface_paths.py`, report at
`tools/audit/ratification_surface_reaim.json`, every citation carrying an **authored verdict with
its reason** and an unclassified citation being a STOP. **It is not a path rewrite, and reading all
of them is what showed why one would have been wrong.** Four kinds were deliberately LEFT:

- **A statement about where a file WAS at a named past commit** — [[OI-285]]'s table of state at
  `b6be14097e` (*"absent from the commit"*, *"untracked"*) and its record that phase 1l committed the
  seven *"IN PLACE, at their current paths"*. Re-aiming those would make the record assert a
  directory that did not exist at that commit.
- **A quotation of another surface's wording**, which re-aiming would silently edit.
- **The BODY of a ratification surface** — **D-249** makes the surface part of the ruling, and
  [[OI-285]]'s own resolution says a surface that has been tidied is no longer the surface that was
  ratified. Those citations also still resolve, both files now sitting in one directory.
- **A generated file** — `decisions/group_*.md` renders from `backbone_decisions.json`, so the
  citation was corrected at the source and the rendering followed.

**And the dispatches were LEFT for a stated reason**, not overlooked: `.gitignore` excludes
`/cc_instruction_*.md` and `/cc_*.md` as a class, so they are not in the record, and they are another
wave's working instruction.

**Verification, at the committed tree:** `gen_cluster_dispositions.py --verify` reports
cross-references resolving ALL and every verbatim quote found at its cited home; the seven anchors
the same wave's `CLAUDE.md` note drifted were re-aimed **from the drift report's own numbers, one by
one**, and re-verified to zero drift. The census was then re-derived and every citation that remains
bare is one of the deliberate LEAVEs above — the artifact carries a `carries_directory` flag per
citation so a later run can tell a deliberate leave from a miss.
