## The finding

`tools/audit/shell_read_guard.py` decides a segment by taking its FIRST token, resolving that to a
utility name, and testing the tokens after it for a repository path. A command whose first token is
an interpreter or a shell — `powershell.exe`, `bash`, `python` — is therefore classified on that
first token alone, and the working-tree read it carries in a quoted argument is never looked at.

**Measured at the guard's own `decide()` over the extended corpus, never reasoned from the source.**
Four rows of `FORBIDDEN` are reported MISSED by `--establish` at HEAD, with the utility set already
widened for the PowerShell dialect:

- the three commands the [[OI-345]] session actually issued, each spelled
  `powershell.exe -NoProfile -Command "<cmdlet> <repository path> …"` — a line count of `STATUS.md`,
  an existence-and-size listing of working-tree files, and a search of `DECISIONS.md`;
- `python -c "print(sum(1 for _ in open(r'C:/s/MS/STATUS.md')))"` — a line count of a working-tree
  file obtained through an interpreter.

Every one is the read **D-253** forbids, and every one is admitted with the reason string *"no text
utility is aimed at a repository path"*.

## Why widening the name set does not reach it, which is the point of rowing it separately

The 2026-08-08 act widened the utility set with the whole PowerShell reading family and its aliases,
and detection on the forbidden corpus rose sharply — every BARE and every ALIASED form of the
dialect is now denied. **These four did not move, and no addition to a name set can move them**: the
name that would have to be matched is not the command's first token, it is text inside a quoted
argument that the lexer correctly keeps as ONE token. Reaching into that token means recognising
which parameters carry a nested command and re-running the whole decision on their contents —
a **second behaviour change**, and **D-436** makes changing a mechanism the user's ruling rather
than a session's.
