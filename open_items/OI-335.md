# OI-335 — A count of outstanding work was the MEMBERSHIP of a list of asks, inside the artifact a phase-1 completion statement would rest on — and the per-row state was an authored field that a later wave superseded by appending a second one beside it

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Found 2026-08-04 (CC) by checking assumption A1 of the dispatch
`cc_instruction_phase1_delegations_and_corrections.md` at the generator, as ruling R4 ordered.**
This is the [[OI-283]] shape — a recorded finding never marked discharged becoming a count of work
that is no longer owed — one level up, inside a generated artifact.

## What was wrong, both halves checked at the object

### (1) The count was the list's length

`tools/audit/gen_phase1_completion_inventory.py` reported
`the_shape_of_what_remains.complete_half.documents_awaiting_a_delegation_only_the_user_may_write` as
`len(reg["write_list"])` — the **membership** of the OI-293 / OI-327 write list.

The write list is the record of what was ASKED FOR: each row carries the draft delegation wording and
the reason the record means to keep that home, and **#12 keeps a satisfied ask in it rather than
deleting it.** So its membership counts asks ever made, which is a different quantity from asks
outstanding and is always the larger one.

Derived at HEAD from the delegation grades and the home data, the outstanding figure is a small
fraction of the membership — **and the derivation additionally names a document the write list never
carried**, so the list was wrong in both directions at once about *which* documents are outstanding.
Every figure and every identity is generated at
`tools/audit/decisions/outstanding_delegations.json`; none is restated here (**D-431**).

### (2) The per-row state was an authored field, and a later wave appended a second one beside it

Each write-list row carries an authored `disposition_2026_08_04`. READ WAVE 6 then ANSWERED two of
those rows and recorded the answers in a **new** field, `disposition_2026_08_04_wave6`, appended
beside the first rather than replacing it (correctly, under #12).

The completion inventory's `the_write_list_state` block read only the first field. It therefore
published **"NOT WRITTEN — WITHHELD"** for `cowork_layer6_grouping_design.md`, whose delegation the
user HAD written, and for `cowork_layer1_tone_collection_design.md`, which the user had **RULED** is
not a delegation target at all. Both statements were false at HEAD on the surface a completion
statement would be read against.

## What was done, and why the remedy is not a status field

**The list is KEPT and its state is DERIVED.** The dispatch offered two options — give the write list
a state field, or retire it in favour of the derived view — and asked for the reason to be recorded.
Neither, exactly:

- **Retiring the list loses what it is for.** It carries each draft wording and each reason the
  record means to keep that home; those are #12 evidence and no derivation reproduces them.
- **A status field would be the same defect a third time.** The list ALREADY has an authored
  disposition field per row, and that field is precisely what went stale — twice, in the same wave,
  by the mechanism half (2) describes. A third authored field would fail the same way.

So: the state is derived at `tools/audit/decisions/outstanding_delegations.json`
(`gen_outstanding_delegations.py`), which imports the delegation grades from
`gen_phase1p_delegation_bar.FORMS` and the population from `gen_home_classification.home_population`
rather than restating either (#6); the completion inventory now takes both the figure and the
per-member state from that derivation; and `section_home_criterion` states in its own data that its
membership is **not** a count of outstanding work.

The general rule is homed at `cowork_audit_protocol.md` beside **D-431**, whose shape it generalizes:
register entry **D-640**.

## Why this GATES

**D-438**'s test. The subject is an INSTRUMENT — a generated artifact and the generator behind it —
that a phase-1 completion claim would rest on, and its figure was wrong in a known direction. That is
squarely *"an instrument a measurement depends on"*. Independently, a figure published as measured
and derived by counting a list's length is an establishment matter (#19), which D-438's starred
clause makes gating whatever its subject.

## What is NOT affected

No decision, no home, no status and no measurement of the analysis. The write list's own content is
unchanged and nothing was deleted from it. What was wrong is a count and two state labels ABOUT the
delegation work.
