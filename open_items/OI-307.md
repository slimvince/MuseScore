# OI-307 — The documented corpus regeneration produces LEGACY output into the PRODUCTION corpus directory, and the manifest cannot tell the two arms apart

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1x, Task 4.2), auditing every
command reference for the `--joint-inference` omission.**

## The three facts, each read at the object

1. **The flag is opt-in.** `jointInferenceDir` is initialised empty at `tools/batch_analyze.cpp:4917`
   and the joint path runs only under `if (!jointInferenceDir.empty())` at `:5590`, returning before
   the legacy `analyzeScore` pipeline. **Without the flag, `batch_analyze` runs the legacy pipeline** —
   the dormant one awaiting deletion at the OI-180 retirement map.

2. **The documented regeneration omits it, and writes into the production directory.**
   `BUILD_AND_TEST.md` §2 and `CLAUDE.md` gate block (C) both give
   `run_bach_preset.py --preset Baroque --output-dir tools/corpus/baroque` with no flag.
   `run_bach_preset.py` **clean-slates** its output directory before regenerating, and
   `tools/corpus/<preset>` is exactly what `tools/a8_rebaseline_measure.py` reads for the block-(A)
   hard stop (`:290-294`, default corpus root `tools/corpus`).

3. **The manifest records no inference arm.** `tools/corpus/baroque/corpus_manifest.json` carries the
   binary's path/size/mtime, the per-score fingerprints, `complete`, `corpus`, `expected_count`,
   `git_hash`, `music21_version`, `ours_count`, `preset` and `schema` — and **no field saying which
   arm produced the `.ours.json` files**. Its `git_hash` today is `d615152c51`, which is the OI-178
   adoption provenance CLAUDE.md gate block (A) names, so the corpus on disk IS the joint-estimator
   one.

## Why the three together are a defect and not a documentation nit

Following the documented command replaces the joint-estimator corpus with legacy output **in the
directory the hard stop reads**. Every column in gate block (A) — root-agree, RN-agree, both key
columns, and the class-(b) hard-stop duration — is then measured on the legacy pipeline against a
joint-estimator reference. The comparison would report a large regression that is not a regression, or,
worse, a change in the joint arm that the legacy numbers happen to mask.

**And the existing contamination guard cannot catch it.** `characterise_bir_false.validate_corpus_dir`
verifies that the `.ours.json` fingerprints match the manifest that ships beside them. A wholesale
regeneration writes both together, so a swapped-arm corpus is internally consistent and validates
cleanly. The guard was built against a different failure (preset contamination in a shared directory)
and is correct for that one; the arm is simply not a thing it can see.

## What is NOT in doubt

That block (C)'s flag omission is **right for what block (C) is**: the `52/24/52` case-identity sets are
LEGACY-pipeline figures, and measuring them through the joint estimator would produce numbers about a
different system. The defect is the OUTPUT DIRECTORY and the silence about which arm ran — not the
missing flag on that particular diagnostic. This is where the phase-1x dispatch's assumption A3 came
back partly refuted: the omission is defensible, the destination is not.

## The remedies, none taken here

- **The directory:** send the retired batch diagnostic to its own directory. `BUILD_AND_TEST.md` now
  warns rather than redirecting, deliberately — `CLAUDE.md` gate block (C) states the same commands, and
  changing a procedure a user-ratified surface also carries is a ruling, not a session's edit.
- **The manifest:** record the inference arm (and the flag's argument) as a stamped field, and have
  `validate_corpus_dir` refuse a corpus whose arm does not match what the caller asked for. That is a
  schema change to a committed artifact and an instrument change under **D-436**, so it owes its own
  establishment — a corpus regenerated on the wrong arm must actually be detected, and a correct one
  must not be refused.
