# OI-307 — The documented corpus regeneration produces LEGACY output into the PRODUCTION corpus directory, and the manifest cannot tell the two arms apart

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1x, Task 4.2), auditing every
command reference for the `--joint-inference` omission.**

## The three facts, each read at the object

1. **The flag is opt-in.** `jointInferenceDir` is initialised empty at `tools/batch_analyze.cpp:4917`
   and the joint path runs only under `if (!jointInferenceDir.empty())` at `:5590`, returning before
   the legacy `analyzeScore` pipeline. **Without the flag, `batch_analyze` runs the legacy pipeline** —
   the dormant one awaiting deletion at the OI-180 retirement map.

2. **The documented regeneration omits it, and writes into the production directory.**
   `BUILD_AND_TEST.md` §2 and `CLAUDE.md` gate block (C) both give
   `run_bach_preset.py --preset Baroque --output-dir tools/corpus/baroque` with no flag.
   `run_bach_preset.py` **clean-slates** its output directory before regenerating, and
   `tools/corpus/<preset>` is exactly what `tools/a8_rebaseline_measure.py` reads for the block-(A)
   hard stop (`:290-294`, default corpus root `tools/corpus`).

3. **The manifest records no inference arm.** `tools/corpus/baroque/corpus_manifest.json` carries the
   binary's path/size/mtime, the per-score fingerprints, `complete`, `corpus`, `expected_count`,
   `git_hash`, `music21_version`, `ours_count`, `preset` and `schema` — and **no field saying which
   arm produced the `.ours.json` files**. Its `git_hash` today is `d615152c51`, which is the OI-178
   adoption provenance CLAUDE.md gate block (A) names, so the corpus on disk IS the joint-estimator
   one.

## Why the three together are a defect and not a documentation nit

Following the documented command replaces the joint-estimator corpus with legacy output **in the
directory the hard stop reads**. Every column in gate block (A) — root-agree, RN-agree, both key
columns, and the class-(b) hard-stop duration — is then measured on the legacy pipeline against a
joint-estimator reference. The comparison would report a large regression that is not a regression, or,
worse, a change in the joint arm that the legacy numbers happen to mask.

**And the existing contamination guard cannot catch it.** `characterise_bir_false.validate_corpus_dir`
verifies that the `.ours.json` fingerprints match the manifest that ships beside them. A wholesale
regeneration writes both together, so a swapped-arm corpus is internally consistent and validates
cleanly. The guard was built against a different failure (preset contamination in a shared directory)
and is correct for that one; the arm is simply not a thing it can see.

## What is NOT in doubt

That block (C)'s flag omission is **right for what block (C) is**: the `52/24/52` case-identity sets are
LEGACY-pipeline figures, and measuring them through the joint estimator would produce numbers about a
different system. The defect is the OUTPUT DIRECTORY and the silence about which arm ran — not the
missing flag on that particular diagnostic. This is where the phase-1x dispatch's assumption A3 came
back partly refuted: the omission is defensible, the destination is not.

## The remedies, none taken here

- **The directory:** send the retired batch diagnostic to its own directory. `BUILD_AND_TEST.md` now
  warns rather than redirecting, deliberately — `CLAUDE.md` gate block (C) states the same commands, and
  changing a procedure a user-ratified surface also carries is a ruling, not a session's edit.
- **The manifest:** record the inference arm (and the flag's argument) as a stamped field, and have
  `validate_corpus_dir` refuse a corpus whose arm does not match what the caller asked for. That is a
  schema change to a committed artifact and an instrument change under **D-436**, so it owes its own
  establishment — a corpus regenerated on the wrong arm must actually be detected, and a correct one
  must not be refused.

## 2026-08-03 (CC, phase 1y) — the manifest half is CLOSED, and the arm turned out to be readable at the object all along

**The premise that made this cheap, and that neither the row nor the dispatch had:** every
`.ours.json` already stamps its own producer. `tools/batch_analyze.cpp:4695` writes
`"analysisPath": "joint"`; the standard writer at `:1448` writes `"batch"`. So the arm of an
existing corpus was never a matter of remembering which command was run — it is readable per file,
which is what turned a back-stamp from an assertion into a measurement (#15).

**Delivered.** `corpus_manifest.json` is at **schema 2** and carries `inference_arm` plus the two
sources it was derived from (`inference_arm_requested`, from the invocation;
`inference_arm_observed`, from the files) and `joint_inference_dir`.
`characterise_bir_false.validate_corpus_dir` takes an `expect_arm` and refuses a mismatch;
`a8_rebaseline_measure.py` declares `joint` — the arm every gate block (A) baseline was measured
on — with `--expect-arm` to state a different intent. A directory mixing arms is refused
outright. `run_bach_preset.py` exits non-zero if the flag and the produced files disagree. All of
it measured, both directions, at `tools/audit/corpus_arm_establishment.json` (eight probes, each
building a real corpus and offering it to the production validator), including the negative
control that the fingerprint guard still fires.

**Task 3's answer: A1 HOLDS, and there is no #13 STOP.** All three gate corpora are joint-arm
output — 352/352 files each, unanimous, `git_hash d615152c51`, timestamps 2026-07-26, which is the
OI-178 adoption provenance CLAUDE.md gate block (A) names. Back-stamped with that evidence and the
citation. 47 of 50 corpus directories established (the 3 gate dirs joint, 44 experiment dirs
legacy); the three `fullspine_*` dirs are left ARM-UNKNOWN because their files stamp
`"analysisPath": "fullspine"` — a diagnostic dump, not a corpus arm — and guessing was refused.
Record at `tools/audit/corpus_arm_backstamp.json`.

**One premise of the dispatch did not hold, and it matters.** Task 3 says "for each **committed**
corpus directory". `.gitignore:26` ignores `/tools/corpus/`: the corpus is **not under version
control**. There is no commit that produced these directories and no git object to compare them
against — so "the commit that produced the directory" was not available as evidence, and the
manifest is the whole of the corpus's provenance record. That makes the stamp more load-bearing
than the row assumed, not less.

**Still open, and why this row does not close:** the DIRECTORY half. Block (C)'s commands still
clean-slate the production corpus, and detection is not prevention. Rowed separately as
[[OI-312]], because redirecting a procedure a user-ratified surface states is a ruling.
A third site with the same omission and a different consequence is [[OI-313]].

**The declared, bounded transition (#23).** A manifest predating the field reports ARM-UNKNOWN:
loud, named in the output, not a silent pass, and not a hard failure. Retirement condition, stated
in the code at `characterise_bir_false.ARM_UNKNOWN_IS_FATAL` and here: once every corpus a
measurement reads carries an established arm, that flag flips to True and probe 5 of the
establishment flips with it.

## 2026-08-04 (CC, phase 1z, Task 5.2) — an addition to the resolution note above: the lesson, stated for the next session

**The arm was ALWAYS readable per file.** `tools/batch_analyze.cpp:4695` writes
`"analysisPath": "joint"`; the standard writer at `:1448` writes `"batch"`; `:3443` writes
`"fullspine"` for the diagnostic dump, which is why the three `fullspine_*` directories were left
ARM-UNKNOWN rather than guessed. That per-file stamp is what turned the back-stamp from an
**assertion** about which command someone once ran into a **reading of the object** (#15) — the
difference between a record that could only be believed and one that can be checked.

**Why this is worth stating beyond this row.** Neither the row nor the phase-1y dispatch knew the
stamp existed. Both were written as though the arm of an existing corpus were unrecoverable, and the
remedy they framed was a new field to be filled in from memory of the invocation. The field was still
worth adding — it records the caller's *intent* alongside the object's *report*, and probe 7 exists
because those two can disagree — but its value came from being derivable, not from being declared.

**The rule for a session that meets the next provenance gap: look for an existing stamp on the object
before designing one.** A generated artifact very often already carries what it was made by; the
question "can I read this off the files?" costs one grep and is the difference between an
establishment (#19) and an assertion. Where the answer is no, say so and design the field — but say
it having looked.
