# OI-356 — The open/resolved test searches the whole status cell for the resolved mark, so a cell that mentions another row's mark reads as resolved

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer (the open-items index's own row parser). Rowed
2026-08-09 (CC, `cc_instruction_return_continuation_3.md`, Task 0).**

## How it was observed

Task 0 wrote the user's Ruling 18 onto [[OI-354]]'s index row. Among the things that ruling settles
is that [[OI-289]]'s completed-verification status is **not** withdrawn, and the sentence recording
it named that status with its own mark. The row stayed OPEN and its text said so in words.

The task-boundary guard run then reported **five** derivations failing where the committed state
carried one, and their messages named OI-354: *"authored verdicts for rows that are not open
first-cut candidates (the register moved under the table)"*, and, in the four that import it,
*"the committed apparatus declaration carries verdicts for rows the INDEX no longer carries open"*.

**It was diagnosed at the tool and then confirmed in both directions**, rather than being inferred
from the message: removing the mark from the status cell — with the sentence's meaning unchanged,
carried in words instead — makes all five pass.

## The cause, read at the tool

`tools/audit/gen_nongating_apparatus_rows.parse_rows` splits an index row into its six cells and
computes the row's open state as **the resolved mark does not occur anywhere in the status cell**.

That function is **the ONE index parser** (#6). `gen_phase1_completion_inventory.py` imports it by
name — its own comment says *"#6 - one parser"* — and the finish-line machinery follows from there.
So the reading is not one tool's: it is the reading every derivation over the register uses.

## The two halves, and only one of them is loud

1. **LOUD — a row that carries an authored apparatus verdict.** The declaration's own STOP fires and
   names the row, and the tools that import the parser stop with it. **That is the guard working**,
   and it is what happened here: nothing was written on a wrong reading, because the run refused to
   produce an artifact at all.
2. **SILENT — a row that carries no authored verdict.** Nothing cross-checks it. The row leaves the
   open population, and the open-row count, the TRUE-half cuts and the finish line's populations all
   move with it, with no stop anywhere. A reader of those artifacts would see a smaller open set and
   no indication that anything had been mis-read.

The silent half is why this is rowed rather than left as a session remark beside the previous
continuations' two JSON traps.

## What is NOT in doubt

- **No analysis, no analysis input, no corpus of scores, no measurement of the analysis**, no golden
  and nothing in `tools/robust_stop/`.
- **No row's actual status.** A row's status is what its own words say; what this concerns is how a
  derivation reads them.
- **No verdict in the apparatus declaration.** None is reopened, and the observed instance produced
  no artifact.
- **The parser's test is not asserted to be wrong for the case it was written for.** A resolved row's
  status cell does begin with the mark, and the test answers correctly for every row that does not
  discuss another row's status.

## Why nothing was changed

Changing how the index is parsed is a mechanism change **D-436** reserves to the user, and there is
more than one defensible remedy — anchor the test to the START of the status cell, take the status
from a dedicated position rather than by searching prose, or forbid the glyph in status prose and
check for it. Choosing among them is a design call, not a repair.

**The working convention adopted meanwhile, stated so the next session does not rediscover it:**
inside a status cell, name another row's resolved status **in words**, never with the glyph. This
row's own status cell follows it.

## Why it carries the declaration's default

The over-inclusive first cut does not reach this row's subject column, so no authored verdict is
written for it and it carries the default, which is that it GATES — the same handling as
[[OI-352]]'s. **No gating verdict is hand-added**: a non-gating verdict is derived from a cut and
never hand-written ([[OI-319]], [[OI-336]]).

**It is not an establishment obligation on a published rate.** The parser produces populations for
tracking artifacts, not a measured value about the analysis, so the clause that always gates
whatever its subject is not engaged here.
