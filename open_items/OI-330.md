# OI-330 — Writing the Layer-2 delegation made a wave-4 measurement tool's anchor AMBIGUOUS, and the artifact cannot be re-derived without restating a historical measurement

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Found 2026-08-04 (CC, READ WAVE 5) at the guard run, caused by this wave's own act, reported and NOT
fixed.**

## What broke, and why

`tools/audit/decisions/gen_reads4_oi326_application.py` is read wave 4's measurement of the OI-326
ruling — how much of the register's home population the doc-governance split moves. It locates each
quote it cites by a **unique anchor string** in the file it cites, so that the artifact carries the
file's own current line rather than a transcribed number.

One of its anchors is the bare filename `` `cowork_layer2_slicing_design.md` ``. Until this wave that
string appeared **once** in `ARCHITECTURE.md` — inside the *"See …"* citation the wave-4 measurement
graded as a bare appended citation. Ruling **R4** then had this session write the Layer-2 delegation
into the same section, which names the same file again. The anchor now matches **two** lines and the
tool stops:

> `anchor is ambiguous in ARCHITECTURE.md (lines [1329, 1332]): '`cowork_layer2_slicing_design.md`'`

`gen_reads4_oi326_application.py --check` therefore **FAILS**, and it is the ONE guard failure this
wave added to the six standing ones.

## Why neither available repair was taken

**Making the anchor specific again would edit a historical measurement's tool.** The anchor is how
wave 4 identified the line it graded; re-pointing it at the delegation written afterwards would make
the tool cite a line that did not exist when the measurement was made.

**Re-deriving the artifact would restate a historical measurement against a changed population.** The
measurement's own subject is which documents the doc-governance clause reaches and what their
namings are — and this wave's three delegation writes changed exactly that. Re-running it would
report today's population as though it were what wave 4 measured. That is the shape [[OI-301]] and
[[OI-305]] already carry: *a historical artifact destroyed by the regeneration meant to maintain it.*

**And the freeze forbids the third option.** From phase 1z the mechanism set is frozen: a tool defect
is rowed and left unless it blocks a read. It does not block one.

## What is NOT affected

The **measurement wave 4 recorded stands** — the artifact on disk is unchanged and remains the record
of what was measured before the ruling was applied. The **grade this wave's write produces is
separately recorded and current**: `gen_phase1p_delegation_bar.py`'s FORMS table carries the moved
grade with the former one preserved, and its `--check` passes. Nothing about the ruling, the bar or
the three written delegations is in doubt.

A second consequence of the same double-naming is already handled and is noted here so it is not
re-discovered: the delegation-bar tool's own anchor for this document was moved off the bare filename
onto **the delegation's own sentence**, because the filename is no longer unique in that file. Under
`CLAUDE.md` rule **(k1)** the strongest naming governs, so the surviving weaker citation does not
undo the delegation.

## The general lesson, stated so it outlives this row

**A tool that locates a quote by a bare filename is fragile against the project's own correct work.**
Every delegation the user writes names a file that some tool may already be anchoring on, so writing
delegations will keep breaking filename anchors. The durable form is the one the delegation-bar tool
now uses and `gen_live_prohibition_pointers.py` argues for in its own docstring: **anchor on the
sentence, not on the name.** That is a change to the anchoring convention, which is not a session's to
make.
