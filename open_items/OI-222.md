**Section — process / methodology (a self-defeating-instruction finding; DT-20, OI-89's shape)**

**The finding (CC, OI-199 pass 1).** The OI-199 pass-1 dispatch is designed as a BLIND pass: it seals
three findings (S1/S2/S3) until after the freeze commit, so that pass 1's discovery of them — or failure
to — is evidence about the audit method's power (#19 applied to the method). **The blinding was defeated
before Task 1 by two independent leaks, both DT-20 (self-defeating instruction composition):**
1. **`STATUS.md`, a MANDATORY session-start read, carries the full S1/S2/S3 text.** The dispatch
   instructs "Read `CLAUDE.md`, `STATUS.md` and `BUILD_AND_TEST.md` as usual." The current top entry of
   `STATUS.md` (2026-07-28, LATEST — the riding Cowork handoff) states OI-215 verbatim with the exact
   `jointdecoder.cpp:427-430/445/838-841` cites (= S1), the C++-slower-than-Python anomaly with the
   `std::string`-state hypothesis (= S2), and `buildAdapterFacts` `events^1.80` (= S3). This is the exact
   **DT-20 founding instance** (OI-89: "a required session-start read that leaks exactly what a blinding
   requirement withholds").
2. **The dispatch delivered §S inline.** `cc_instruction_oi199_pass1.md` contains §S (S1–S5) in full at
   its foot; it was in front of the auditor from the first turn. No separate sealed file was "opened
   early" — the sealed content was never withheld in delivery.

**Consequence.** The Task-4 reconciliation cannot claim INDEPENDENT (knowledge-free) discovery of
S1/S2/S3 — the auditor had that knowledge from the required reads before Task 1. What the reconciliation
CAN and does report is the knowledge-independent question: do the audit's generated artifacts + a
rigorous code-reading of the dispositioned rows point at each finding's mechanism on their own merits?
(They do — the fire-structure of `candidateStates` + the `V[N]`-empty branch; the `std::string`-keyed DP
in the disposition CSV; the nested-scan `buildAdapterFacts`.) So the pass measured the METHOD's
structural reach, not a blind auditor's recall.

**The remedy (the OI-89 remedy, generalized).** A blind dispatch must cross-check every required read AND
its own body against every withholding requirement in the same dispatch; any file both required and
information-bearing for the withheld topic is a conflict to resolve BEFORE dispatch. Two rules specific
to this recurrence: (a) **do not put a rolling headline that names the withheld findings in `STATUS.md`**
while `STATUS.md` is a mandatory blind-pass read (or blind the pass from `STATUS.md`'s current entry);
(b) **never embed the sealed section in the dispatch body** delivered to the auditor — keep §S in a
separate artifact opened only post-freeze. Relates to [[OI-208]] (the decisions register / process-
hygiene track) and [[OI-219]] (the sibling process finding from the same session — the missing #17(b)
bands). DT-20.

**NOT a code defect; process only.** No build. The pass 1 work (inventory, partition, dispositions)
stands on its own; only the "was it blind" claim is compromised, and that is reported honestly rather
than papered over.
