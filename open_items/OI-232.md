# OI-232 — The canonical architecture document carries five stale or self-contradicting statements about what is live

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section F — doc-sync debt (#10), DT-12. Found by the [[OI-207]] adjudication, 2026-08-01.
Sibling of [[OI-107]] / [[OI-112]] (earlier ARCHITECTURE.md drift rows), but distinct in kind:
these five are not stale *figures*, they are stale statements about **which code is running**.**

## Why this matters more than an ordinary doc drift

`ARCHITECTURE.md:263-264` (register entry D-091) states the document's own authority verbatim:

> **When any doc disagrees with this one, this one wins, and a new ratified decision lands here
> first.**

A reader is therefore instructed to believe this document over every other. All five statements
below are ones a reader would act on.

## The five

**(1) `ARCHITECTURE.md:39-40` — the staged-scope block still says the notation layer is legacy.**
Verbatim:

> **STAGED SCOPE (declared migration state, #23):** the in-app **NOTATION layer stays on the legacy
> L1–L6 pipeline** (`region::analyzeRegions` → `analyzeSection`)

Contradicted by `ARCHITECTURE.md:236` in the same document ("flipped `useJointNotationRecord`'s
default to **ON**"), by `CLAUDE.md` gate block (A) ("STAGED SCOPE — CLOSED AT THE NOTATION SWITCH"),
and at the code by `composingconfiguration.cpp:178` (`setDefaultValue(USE_JOINT_NOTATION_RECORD, Val(true))`).

**(2) `ARCHITECTURE.md:138-139` — the layer sections' scope note has the two surfaces backwards.**
Verbatim:

> The layer sections (L1–L6) below remain the accurate description of the LEGACY pipeline — still
> live on the notation path, dormant-compiled on the batch path.

Since the switch the legacy pipeline is dormant on **both** surfaces. `ARCHITECTURE.md:104-106` says
so eleven lines earlier: "the legacy `analyzeHarmonicRhythm`/`analyzeChord` path remains COMPILED and
DORMANT, selected only by an explicit `useJointNotationRecord = false`".

**(3) The Layer-3 and Layer-4 build-state tags.** `ARCHITECTURE.md:1092` heads Layer 3
"**(Built+Live)**" and `:1146` heads Layer 4 "**(Built+Dormant — not wired; engages with L5)**".
Register entry D-094 makes those tags a decision in their own right — "exactly one build state" per
layer, `ARCHITECTURE.md:986-988`. Neither tag survives the two adoptions: Layer 3's decoder no longer
decides the key on either surface (register entry D-051), and Layer 4's "engages with L5" plan
(`:1153-1154`) was overtaken by the joint estimator without any ruling that names it.

**(4) `ARCHITECTURE.md:1218-1219` — the voice-leading layer is described as not built.** Verbatim:

> **The future voice-leading layer** — the *horizontal* dimension … **not built**

Contradicted by `ARCHITECTURE.md:818-821` in the same document: "**axis-2 status (2026-07-03): the
foundation is BUILT (dormant)** — VL-A voice-linear view + VL-B motion/interval profiles (facts) +
VL-C texture classification". Register entry D-085.

**(5) `ARCHITECTURE.md:762` — the cross-layer confidence contract is recorded as unratified.**
Verbatim, inside §2.15:

> (`cowork_confidence_contract.md`, review amendment A-1, 2026-07-02, ratification-gated)

The contract's own banner says otherwise (`cowork_confidence_contract.md:3`): "**Status: RATIFIED
(user, 2026-07-02).**" A reader of the canonical document alone would conclude that the contract does
not yet bind — which is the precise reading under which the production record arm departs from it
(see [[OI-231]]).

## Disposition

Five one-paragraph doc corrections; **no code change, no decision change**. They are grouped in one
row because they share one cause — the two adoptions (the batch adoption 2026-07-26, the notation
switch 2026-07-27) landed their doc-sync at the blocks they added and not at the older blocks they
falsified. Fix at the next `ARCHITECTURE.md` touch, together with [[OI-107]] / [[OI-112]] /
[[OI-233]] / [[OI-236]] / [[OI-238]], which are all corrections to the same document. **Nothing is
edited here** — the adjudication was read-only, and rewriting a layer specification is a separate,
ratified act ([[OI-208]] ruling 2).
