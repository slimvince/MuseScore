# OI-245 — Three different eligibility rules exist for one Layer-1 note surface; the adapter's grace-note drop contradicts the ratified Layer-2 boundary rule

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — joint module / Layer boundaries (#6). Cross-ref [[OI-239]] (whose difference (1)
this generalizes to the tree).**

One Layer-1 note surface, three consumers, three answers to "which notes count":

- the joint fact adapter admits everything except grace notes, zero-duration notes, and excluded
  staves (`jointfactadapter.cpp:393-399`) — the `plays`/`visible`/`staffEligible` flags are never
  read;
- the Layer-2 slicer applies the three eligibility flags and does NOT drop grace notes — the
  ratified rule says a grace note genuinely opens a boundary by its span
  (`ARCHITECTURE.md:1112-1116`; `slicer.cpp:40-48`);
- the legacy note-model views apply the three flags AND drop grace notes
  (`regiontoneprimitives.cpp:54-57`, `:232-235`).

The adapter's grace-drop is deliberate (parity with the fitting extraction, stated at
`jointfactadapter.h:65`) but recorded in no specification, and it directly contradicts the
ratified Layer-2 statement. One question — note eligibility — needs ONE recorded answer per
declared purpose (#6), with the differences, if intentional, specified where the family design
records the joint module's input surface ([[OI-239]]'s documentation act). Not fixed here.
