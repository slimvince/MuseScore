## The finding, in the ruling's own words

The ruling record states the finding for the row, and it is quoted here rather than paraphrased:

> *"**`CLAUDE.md` is the single point of failure for its own discoverability.** The instructions to
> read `STATUS.md` and `DECISIONS.md`, and the gating rows that tell a session what it may not do,

> proceeds ungoverned and unaware."*

## The four configurations in which no repository file arrives — RELAYED, NOT ENDORSED

The same session named four configurations in which no repository file stands in context at boot.
**They are relayed as its report and are not endorsed by this project; none has been verified
here.**

1. No folder connected at all.
2. Only a subfolder connected, which itself carries no `CLAUDE.md`.
3. No desktop bridge.
4. The file renamed or moved.

## The consequence, which is the part that bites

In those configurations a session on this repository starts with **no repository text, no knowledge
that standing instructions exist, and no signal that anything is missing.** The failure is silent:
**it does not fail loudly; it proceeds ungoverned and unaware.**

The ruling record states the consequence that generalizes it, and it is the reason the row exists at
all rather than the observation about one file:

> *"a ruling is not binding mechanically. It binds only a session that met it."*

## The irony, which is why the row is not trivially closable

> *"**The configuration that gives a deriving session its correct blindness is the same one that
> leaves an ordinary session silently ungoverned.**"*

The two needs — a deriving session that must NOT meet the repository's text, and an ordinary session
that MUST — are served by the same mechanism pointed in opposite directions. That is why this is
rowed as a finding and not as a task whose answer is already known.
