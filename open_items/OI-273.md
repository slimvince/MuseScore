## Why it is a non-conformance

`CLAUDE.md`'s **"Local patches — do not revert"** section carries exactly **two** subsections: the
Windows Snap fix in the `muse` submodule (register entry **D-198**) and the MusicXML declared-mode
import fix (**D-199**). This third edit is in neither, so:

1. **It is not protected.** The section exists so a dependency update or a build script does not
   silently overwrite an intentional change. A patch outside the list has no such protection, and
   nothing in the tree marks the line as deliberately deleted.
2. **It has no distribution disposition.** **D-197** puts a permanent HARD STOP on carrying the
   MusicXML import fix toward `musescore/MuseScore`; this edit has no equivalent statement in
   either direction. The record instead says "Should be reported upstream", and a report was
   drafted (`docs/chordlist_bug_report.md`) and left as a standing submission item
   (`STATUS_ARCHIVE.md:3798`). Whether it was ever posted is not recorded.
3. **It is outside the rule that now governs.** [[OI-241]] was ruled on 2026-08-02 and the
   MuseScore-dependency rule adopted (**D-229**): an edit to MuseScore's own code is admissible
   only for a feature-blocking defect, and each instance is **recorded, distribution-dispositioned
   and user-ratified**. This instance satisfies none of the three, and [[OI-241]]'s own finding
   said "the record holds two instances of the practice (`CLAUDE.md:629-677`)" — so the count the
   ruling was made against was one short.

Not in doubt: the edit's technical justification. It is diagnosed at the source in `b1ba746`'s own
message and in the drafted report, and the sussus double-render it removes is a real MuseScore
parser defect.
