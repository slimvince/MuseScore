# OI-333 — The cluster-disposition layer CANNOT BE REGENERATED at HEAD: six register patterns are invalid regular expressions, and the guard that watches this tool cannot see it

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Found 2026-08-04 (CC, READ WAVE 6) by attempting the regeneration, not by reading — the write path
was run and it crashed.**

## What fails

`python tools/audit/decisions/gen_cluster_dispositions.py` — the WRITE mode, which produces
`cluster_dispositions.json`, `.csv` and `disposition_manifest.json` — **terminates with an uncaught
`re.PatternError`** before writing anything:

> `re.PatternError: multiple repeat at position 3`

raised from `gen_cluster_dispositions.py:407`, `pats = [re.compile(p, re.IGNORECASE) for p in
d.get("patterns", [])]`.

## The cause, enumerated at the data

Six register entries carry a `patterns` string containing **unescaped markdown emphasis** — a
literal `**` — which the regular-expression compiler reads as a repeat operator applied to a repeat
operator. Every one was authored by READ WAVE 5 on 2026-08-04:

| entry | the pattern |
|---|---|
| **D-555** | `a **motion-type-led** feature set` |
| **D-570** | `judged against the **score**` |
| **D-576** | `is largely **key-independent**` |
| **D-577** | `design debt** (wrong cut) from **migration debt` |
| **D-578** | `orphan claims need a **whole-repo** grep` |
| **D-581** | `Not-yet-consumed information is **NOT automatically a defect` |

Every OTHER pattern in the register escapes its emphasis (`\\*\\*`) or avoids it, which is what
makes these six a slip rather than a convention.

## ★ Why the guard did not catch it — the part worth keeping

`gen_cluster_dispositions.py --check` **PASSES**, at this tree and at the committed one, and it is in
the guard list. Its own docstring says why: *"`--check` — Re-reads the emitted artifacts and proves
the coverage guarantee."* It **re-reads**; it does not **re-derive**. So the check proves that the
committed artifact covers every cluster exactly once — which is true — and is structurally incapable
of noticing that the artifact can no longer be produced.

That is a **different failure shape from every row in the [[OI-309]] family**, and the difference is
the finding: those are artifacts that no longer re-derive and whose checks SAY SO. This is an
artifact that no longer re-derives and whose check says nothing, because the check and the
derivation do not share a code path. Under the guard classification made this wave
(`tools/audit/guard_classification.json`), that tool is correctly LIVE — `--verify` locates every
verbatim at its home and the coverage proof is a real invariant — and it is live on the half that
works while the half that is broken is unwatched.

## What is NOT affected

**Nothing is measured wrongly.** The committed `cluster_dispositions.json` and its manifest are the
last successful derivation and their coverage guarantee holds; `--verify` passes 638/638 with every
line anchor correct; `gen_decisions_register.py --check` passes across all 21 emitted files. No
figure anywhere is wrong. What is lost is the ability to REFRESH the disposition layer — so the
27 entries this wave entered, like the 37 wave 5 entered, cannot move a cluster from `unresolved` to
`restates` until this is repaired.

## Why it was NOT fixed

The wave's freeze: a defect found is rowed and left unless it blocks a read, and it blocked none —
the disposition layer has not been regenerated by any read wave, and the register's coverage figures
come from the committed artifact exactly as they did for waves 1 through 5. **The repair is
mechanical and small** — escape the six patterns, or compile with `re.escape` where a pattern is
meant literally — but it changes what the matchers match, which is a measured surface, so it belongs
to a wave that can regenerate and diff the disposition layer rather than to one that cannot run it.

**A second, larger question this row raises and does not answer:** whether `--check` should re-derive
rather than re-read. Making it re-derive would have caught this on the wave that introduced it, and
would catch the whole class; it would also make the check fail for every reason a regeneration can
fail, which is a different guard from the one the record chose. That is a decision about the guard,
not a repair of the data.

## Why this GATES

**D-438**'s test: does the row's subject bear on an instrument a measurement depends on? **It does.**
The disposition layer is the coverage measurement the OI-207 audit reports against — 14,460 clusters,
15,224 occurrences, the unresolved residual — and it is currently unrefreshable. Independently, a
guard whose passing does not mean what a reader takes it to mean is an establishment matter (#19),
and D-438's starred clause makes an establishment obligation gate whatever its subject.

## Note, 2026-08-04 (CC, the phase-1 completion inventory) — THE GUARD HALF IS THE SHARPER ONE, and what it costs backwards

The dispatch that derived what phase 1's completion statement still requires
(`cc_instruction_phase1_completion_inventory.md`, Task 1.4) directed that this be written down
here, and it is a statement about the RECORD, not a new defect.

Of the two halves this row carries — six invalid patterns, and a guard that cannot see them — **the
guard half is the sharper**. The data half is a mechanical slip in six strings and is repaired by
escaping them. The guard half is structural: `--check` **re-reads the emitted artifacts** and the
write path **re-derives** them, and the two do not share a code path, so no possible failure of the
derivation can make the check fail. A guard built that way cannot report the class of defect it
appears to cover.

**What that costs backwards, stated plainly.** `gen_cluster_dispositions.py --check` is in the guard
list and has been reported PASSING by every wave that ran the guard battery. Each of those passes
was true of what the check tests — the committed artifact covers every cluster exactly once, and
`--verify` locates every verbatim at its home — and **narrower than a reader would take it to
be**: none of them was evidence that the disposition layer could still be produced. No figure
anywhere is wrong on account of this, and no wave's verdict is withdrawn; what is withdrawn is the
inference a reader could otherwise draw from those passes about regenerability.

**A1 was settled against this row and it does NOT block.** The same dispatch asked whether phase 1's
completion statement needs this layer regenerable; the derivation is at
`tools/audit/phase1_completion_inventory.json` →
`a1_does_the_completion_statement_rest_on_the_disposition_layer`, and the answer is that the two
halves of phase 1 are read off the register's home data and the open-items rows, neither of which
draws a figure from the disposition layer — and the register's own method declares the harvest a
**backstop, not the backbone**. So the six patterns were **NOT** escaped, the freeze's
blocks-the-work exception was **not** exercised, and this row stands exactly as written.

**The one bound it does place on a completion statement:** no REFRESHED unresolved residual may be
published, and the committed residual may not be described as current — the committed layer was
derived at a smaller backbone than the register now holds, so it overstates what is unresolved at
HEAD in a known direction, by an amount only a re-derivation can give. That bound is recorded in the
same artifact and is not restated here as a figure (**D-431**).
