## The answer in one line

**The row's words are accurate about SCHEDULING and were read as a claim about SURVIVAL.** No
retirement row names this primitive — the row says so itself, two sentences earlier — and that is all
"not currently scheduled to die" establishes. It does **not** establish that the primitive survives,
and at HEAD it does not: **both of its production call sites are on the legacy arm, and nothing in the
record names a consumer for it on either production surface.**

## 1. Every caller, enumerated

`ebr::findTemporalContext` is declared at `regiontonecollector.h:219` and defined at
`regiontoneprimitives.cpp:452`. The complete caller set at HEAD, from a repository-wide search:

| caller | kind | arm |
|---|---|---|
| `regionanalyzer.cpp:921` | production — seeds the Pass-1 `ChordPathDecoder` inside `analyzeRegions` (`:561-1515`) | legacy |
| `notationcomposingbridgehelpers.cpp:240` | production — the notation-namespace wrapper `notation::internal::findTemporalContext` (`:231`) | forwards only |
| `notationcomposingbridge.cpp:651` | production — inside `analyzeHarmonicContextLocallyAtTick` (`:621-688`), the sole caller of that wrapper | legacy |
| `engravingbridge_branch_tests.cpp:724`, `:752`, `:773` | test | — |

So there are **two production call sites and one forwarding wrapper between them**, which is what
[[OI-288]] states. Nothing else calls it: no file under `src/composing/analysis/joint/` names it, and
`tools/` names it only in audit-disposition data and prose, never as a call.

## 2. Are the two call sites on the legacy arm? Yes — established at the branch, not inferred

- **`notationcomposingbridge.cpp:651`.** `analyzeHarmonicContextAtTick` (`:703`) — which
  `ARCHITECTURE.md:4097` records as *"THE funnel, and the path-selection site"* with no other
  production caller — returns `buildNoteContextFromRecord(...)` at `:737` whenever
  `useJointNotationRecord()` is true, and the setting defaults true. The regional path (`:743`) and
  the tick-local fallback (`:753`) both sit below that return. `ARCHITECTURE.md:4098` already records
  the consequence in terms: `analyzeHarmonicContextLocallyAtTick` has **"no production caller"**.
- **`regionanalyzer.cpp:921`.** `analyzeRegions` has exactly two production entry points.
  *(a)* `notation::analyzeHarmonicRhythm` (`notationharmonicrhythmbridge.cpp:131`), which
  `ARCHITECTURE.md:4099` records as *"the only entry that takes a time range — and it is legacy-arm
  only"*; verified at each of its three call sites, every one of which sits below a
  `useJointNotationRecord()` early return — the span emitter (`notationcomposingbridge.cpp:1491-1509`),
  the chord-track write (`notationimplodebridge.cpp:1416-1434`) and the tuning path

  `batch_analyze.cpp:5590-5601` never reaches under `--joint-inference`: that branch runs

**What does carry the deletion is a general statement, not a scheduled row.** [[OI-180]]'s dated note

## 5. The false-negative paths — the ways it could survive that this check would not see (#17e)

An insulation claim must enumerate how it can be wrong. Six paths, stated:

1. **The FILE is not the FUNCTION.** `regiontoneprimitives.cpp` is a mixed unit — the audit's own
   flags call it a *"MIXED LAYER GRAB-BAG"* (`tools/audit/gen_dispositions.py:119`) — and other
   symbols in it (`soundingAt`, `buildTones`, `weightedPcView`, `staffIsEligible`,
   `pitchContextOverSpan`) have their own lifetimes. This check establishes nothing about the file,
   only about the primitive. *(Measured in passing, and NOT relied on: at HEAD `pitchContextOverSpan`'s
   only production consumer is `keymodesequence.cpp:89`, itself reached through `analyzeRegions`; and
   nothing under `src/composing/analysis/joint/` names any of these symbols. That points the same way,
   but it is a second question and is not answered here.)*
2. **Dormant is not deleted, and the flag is a setting.** `useJointNotationRecord` can be set false,
   which re-selects the legacy arm at runtime; the reverse map ([[OI-180]], `cowork_prefit_gates.md`
   item 5) keeps that exit open by design. "Unreachable" here means *unreachable at the default*, not
   *uncompilable*.
3. **The measurement and diagnostic surface is not the product.** `batch_analyze` without
   `--joint-inference` still runs `analyzeRegions`, and `CLAUDE.md` gate block (C) still presents that
   path's diagnostic (`characterise_bir_false.py`) as runnable. Deleting the primitive removes a
   diagnostic the record describes as available. Dormant on the shipped product ≠ unused by the
   project.
4. **The tests are a consumer.** Three direct test call sites pin its behaviour; a deletion must
   dispose of them, and a decision to keep the tests is a decision to keep the function.
5. **An unnamed future need.** The record's silence is not proof. This primitive computes exactly the
   neighbour-chord facts a future function layer might want, and D-404 defers rather than forbids —
   what it forbids is building an interim home now.
6. **This check reads control flow, not execution.** It establishes which branch is taken at the
   default setting; it does not measure that the branch below is never entered on real repertoire.
   That measurement is [[OI-288]] half (a) and is scheduled into phase 2.
