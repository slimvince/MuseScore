# OI-305 — `gen_home_classification.py --check` reports STALE at the committed tree

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — instrument / measurement layer. Rowed 2026-08-03 (CC, phase 1w) by running the guard
set the dispatch asks for, deriving the list from what exists rather than from a named list.**

## What the check reports

Two separate failures, printed under the same `STALE vs the files:` heading:

1. **Four `home_section` fields do not re-derive** — D-321, D-322, D-323 and D-324, all homed in
   `docs/scoring_model.md`. The recorded field names a section; re-deriving it from the document's own
   headings and the entry's own cited line yields a different one. That re-derivation is exactly the
   property the register's own preamble claims for the field — *"re-derived by a check, so it cannot
   go stale when a heading moves"* — so the check is doing what it exists for.

2. **`phase1q_reclassification.json` does not re-derive.** This is a different kind of failure: a
   generated artifact that does not reproduce.

## Pre-existing, and how that was established

The check's inputs are `backbone_decisions.json` and the home documents. **This wave modified
neither** — verified through `tools/audit/changed_paths.py`, which reports the changed-path list and
nothing else. Nothing in the phase-1w work touches the decisions data or `docs/scoring_model.md`.

The reason it surfaced now rather than earlier is worth recording: **this check is not in the guard
list any recent wave reported running.** The phase-1v, 1u, 1s and 1r reports each enumerate the
guards they ran — the register `--check`, the disposition `--verify`, the open-items living check,
the local-patches check, the armed-guard check, the partition and non-gating generators — and the
home classification check is in none of them. It was run here only because the dispatch says to
derive the guard list from what exists.

## Why the two halves need separating before either is fixed

A **stale section field is a pointer**, which the non-gating declaration's own line calls apparatus.
A **generated artifact that does not reproduce is a #19 matter**: reproducibility is one of the three
things that positively establish an instrument, and this artifact is the record of a
re-classification pass over the whole home population — the thing a later reader would consult to
learn what moved and why.

It is also possible that the second half is expected: the classification has been re-run and
re-applied since phase 1q (the phase-1r write list moved six documents), so an artifact frozen at
phase 1q may be *meant* not to reproduce against today's authored inputs, exactly as the split
check's `--split-baseline` mode is meant to be historical ([[OI-301]]). **That is a diagnosis, not a
verdict, and it is why this row asks for one rather than for a fix.** If the artifact is historical,
what is owed is the epoch treatment the classifier already uses for its class fields, not a
regeneration that would overwrite the record of what phase 1q found — the [[OI-301]] hazard.

## Why nothing was fixed here

Correcting a register field is action on the decisions register, and the phase-1w dispatch is a
gathering wave whose only licence to act is over a LEGACY mark it establishes wrong. Regenerating the
phase-1q artifact without the diagnosis above risks exactly the [[OI-301]] failure.
