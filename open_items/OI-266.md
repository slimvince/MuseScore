# OI-266 — The session handoff's working-protocol standing rules have no specification home

## The finding

`cowork_handoff.md` carries a block of standing rules for how the work itself is run. Six of them
are decisions in the register's sense — a stated rule, most with a named ratifier and a date — and
none was in the register before this pass:

| entry | the rule | ratifier and date in the record |
|---|---|---|
| D-249 | The whole decision surface is delivered as user-visible text before any choice question | user mandate 2026-07-05 |
| D-250 | Dispatches are written only when they are next; a parked instruction is revalidated first | not stated |
| D-251 | A running dispatch is never interrupted or steered mid-flight | user, 2026-07-05 |
| D-252 | One side writes the instruction files and the other executes them, never the reverse | not stated |
| D-253 | Working-tree files are read with the file tools; shell access is limited to git object queries by explicit hash | user mandate 2026-06-21 |
| D-254 | Investigate by default; never ask the user whether to investigate or proceed | user mandate 2026-06-14 |

Each is entered `home_is_layer_spec: false`, `nonspec_kind: "unhomed"` — **recorded only on a
tracking surface** — which is [[OI-240]]'s own classification: a session handoff block is a place
for tracking work, not a home for a standing decision.

## What this says about the phase-1 homing pass

The homing acts drove the register's tracking-surface-only count to **0**. That zero was true of
the 231 entries the register then held; it was not true of the repository. Adding these six moves
the count 0 → 6. The homing pass is not wrong — it homed what it was given — but the count cannot
be read as "no standing decision is left on a tracking surface" until the enumeration behind it is
itself complete.

`CLAUDE.md` already treats this surface as carrying standing rules: its provenance paragraph names
"the ⛔ TOTAL UNIFICATION rule (`cowork_handoff.md`)" among the "companion standing rules
elsewhere". So the question these six raise is not whether they bind — they plainly do — but
whether a handover document is their home, and if not, which specification is.

## Disposition

**For the NEXT homing wave, not for this pass.** The residual second pass may not edit
`ARCHITECTURE.md` (its dispatch forbids it) and may not ratify a decision. What is owed:

1. The user ratifies (or corrects) the six register entries — they are in the pass report's
   ratification queue.
2. The homing act itself: decide the owning home for each. Candidates the record already suggests
   are `CLAUDE.md` (which holds the project's other standing process rules, register group T) and
   `cowork_design_doc_template.md` (the ratified home of the writing standards) — the choice is a
   decision, not a mechanical move, so it is not made here.
3. Whether "recorded only on a tracking surface" is even the right classification for a rule that
   governs the working protocol rather than the system is a question for the user: the register
   already distinguishes a **decision about the process, correctly homed** (26 entries) from an
   **unhomed** one, and the line between them was drawn when the only process rules in the register
   lived in `CLAUDE.md`.

**Dated note — 2026-08-02 (CC, the phase-1d enumeration wave, Task 0): the six are homed. The split,
and the one judgment inside it that the reader should be able to dispute.**

Point 1 of the disposition above is discharged: the user ratified D-232…D-254 at `91802e4d37`. Points
2 and 3 were made by the dispatch, which is where they belonged — this row said the choice "is a
decision, not a mechanical move", and the dispatch made it. **The split is by what each rule
governs**, not by where it was found:

| entry | homed at | why there |
|---|---|---|
| D-249 the whole decision surface before any choice question | `CLAUDE.md` Conventions | a session-method rule about how the user is asked; the Conventions section already holds the other user-interaction rules |
| D-253 file tools for working-tree reads; shell only for git objects by hash | `CLAUDE.md` Conventions | a session-method rule about how the record is read |
| D-254 investigate by default | `CLAUDE.md` Conventions | a session-method rule; it operationalizes principle #5, which lives in the same file |
| D-252 one side writes instructions, the other executes | `cowork_audit_protocol.md`, new dispatch-protocol section | governs how a dispatch is commissioned |
| D-250 no dispatch ahead of need; a parked instruction is revalidated | same | governs when a dispatch is written |
| D-251 no mid-flight steering; instructions self-sufficient | same | governs how a dispatch is run |

**The judgment worth disputing, stated so it can be:** `cowork_audit_protocol.md` is titled *The
Certification-Audit Protocol*, and its P1–P9 are audit steps. The three dispatch-protocol rules are
**wider than audits** — they govern every dispatch. Two things make it the least-bad home rather than
a category error: the document already carries two rules of exactly this kind (P5's withheld-finding
rule constrains how a dispatch is *written*; P8's blind-pass-first constrains how dispatches are
*sequenced*), and every audit in it is commissioned as a dispatch, so the protocol has no meaning
without them. The new section says all of this in its own lead-in rather than absorbing the rules
silently. If the user prefers them in `CLAUDE.md` beside the session-method three, or in a document
of their own, moving them is a one-commit act and this note is the record of why they are here.

**On D-253's scope.** Homing it unqualified into `CLAUDE.md` would have contradicted the same file's
mandatory build, test and bash-rule sections. The scope was not invented to resolve that: the record
states it — the rule sits under the heading *COWORK MUST NOT HALLUCINATE OR ASSUME — VERIFY AT
SOURCE*, and D-252's own text spells the same restriction out as one of the things "Cowork MAY" do.
The homed entry cites both and says the build and measurement commands are unaffected.

Register: homes moved, verbatims re-taken from the new homes by line range (never retyped), former
homes moved into provenance (#12), `nonspec_kind` **unhomed → process** on all six. The register's
*recorded only on a tracking surface* count goes **6 → 0** — and, as this row warned, that zero is
only as strong as the enumeration behind it. This wave's own reading list is the measure of how
strong that is; see the [[OI-207]] note of this date.
