# OI-246 — Concert and written pitch are mixed inside one record on transposing instruments: the pitch class is sounding, the spelling is written, the signature prior is concert

> STATUS IS AUTHORITATIVE IN THE INDEX (OPEN_ITEMS.md) — this file carries narrative and provenance only and is NEVER the status of record

**Section D — joint module / input representation (declared to Cowork). Compounds [[OI-243]].**

On a transposing staff (B♭ clarinet, F horn…) with the score displayed in written pitch:

- the note's pitch class comes from the SOUNDING pitch — `nn.pitch = Note::ppitch()`
  (`note_model.cpp:93`; `note.cpp:2539-2560`);
- the note's line-of-fifths spelling comes from the WRITTEN tpc — `nn.tpc = Note::tpc()` returns
  the written-pitch spelling when the concert-pitch style is off (`note_model.cpp:94`;
  `note.cpp:826-829`, `:700-703`);
- the key-signature prior is the CONCERT key (`jointfactadapter.cpp:360`, `kse.concertKey()`).

So for one note the pitch-class evidence and the spelling evidence disagree by the transposition
interval, and the spelling also disagrees with the signature the prior reads — the spelling
factor and the key prior are fed contradictory evidence. [[OI-243]] establishes that the spelling
factor is exactly where representation errors move committed readings and boundaries. No layer
statement records which representation the spelling field must use (`note_model.h:81` documents
the pitch field only). Unexercised by the chorale fit corpus (non-transposing); a first-class
input-representation decision for the family design's input-surface specification. Not fixed here.
